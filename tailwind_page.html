Setup With The CDN

Use this to test an idea in one HTML file with nothing installed. The browser builds the CSS on every page load, so it is only for testing. Use the Vite or CLI setup below for anything you hand to a client. This page is written for Tailwind 4.3.

Full HTML page with the Tailwind CDN

<!DOCTYPE html>
<html lang="en">

<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Tailwind Test</title>
  <script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script>
</head>

<body class="bg-gray-100 p-8">
  <h1 class="text-3xl font-bold text-blue-700">Tailwind is working</h1>
  <p class="mt-2 text-gray-600">If this text is gray and the heading is blue, you are set.</p>
</body>

</html>

Add your own colors and fonts to the CDN page

This goes in the head, right under the CDN script. Everything in the Customize section of this page works inside this style tag.

<style type="text/tailwindcss">
  @theme {
    --color-brand: #0f766e;
    --font-display: "Georgia", serif;
  }

  @layer components {
    .btn {
      @apply rounded-lg bg-brand px-4 py-2 font-semibold text-white;
    }
  }
</style>

Setup In React With Vite

Tailwind 4 does not need a tailwind.config.js file or an init command. You install two packages, add one plugin to Vite, and import Tailwind in your CSS. Your theme goes in the CSS file too. Do this inside the client folder.

Install Tailwind

npm create vite@latest client -- --template react
cd client
npm install
npm install tailwindcss @tailwindcss/vite

client/vite.config.js

import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [react(), tailwindcss()],
});

client/vite.config.js with the API proxy for a full stack project

This is the same file for a project with an Express server. Calls to /api go to the server on port 3000.

import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [react(), tailwindcss()],
  server: {
    proxy: {
      "/api": "http://localhost:3000",
    },
  },
});

client/src/index.css

Delete everything in this file and put in this one line. The CSS Vite gives you fights with Tailwind.

@import "tailwindcss";

Test it in client/src/App.jsx

const App = () => {
  return (
    <main className="grid min-h-dvh place-items-center bg-gray-100">
      <h1 className="text-4xl font-bold text-blue-700">Tailwind is working</h1>
    </main>
  );
};

export default App;

Start the site

npm run dev

client/tailwind.config.js if you want one

This is optional. You only need it for an older project or a plugin that asks for it. Tailwind 4 does not find this file on its own, so the next snippet has to point to it. On a new project, use the theme in the Customize section instead.

/** @type {import('tailwindcss').Config} */
export default {
  content: ["./index.html", "./src/**/*.{js,jsx}"],
  theme: {
    extend: {
      colors: {
        brand: {
          100: "#ccfbf1",
          600: "#0d9488",
          700: "#0f766e",
        },
      },
      fontFamily: {
        display: ["Poppins", "sans-serif"],
      },
      borderRadius: {
        card: "1.25rem",
      },
    },
  },
  plugins: [],
};

Load tailwind.config.js from client/src/index.css

@import "tailwindcss";
@config "../tailwind.config.js";

Setup In Plain HTML With The CLI

Use this for a portfolio or a small client site with no React. The CLI watches your HTML and writes one small CSS file with only the classes you used.

Make the project

mkdir my-portfolio
cd my-portfolio
npm init -y
npm install tailwindcss @tailwindcss/cli
mkdir src css
touch index.html src/input.css

src/input.css

@import "tailwindcss";

Scripts for package.json

"scripts": {
  "dev": "tailwindcss -i ./src/input.css -o ./css/output.css --watch",
  "build": "tailwindcss -i ./src/input.css -o ./css/output.css --minify"
}

Link the CSS in index.html

Link css/output.css, not src/input.css. The browser can only read the built file.

<!DOCTYPE html>
<html lang="en">

<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My Portfolio</title>
  <link rel="stylesheet" href="css/output.css">
</head>

<body class="bg-white text-gray-900">
  <h1 class="p-8 text-4xl font-bold">Hello</h1>
</body>

</html>

Run it while you work, then build before you upload

Leave the first command running in one terminal. Run the second one when you finish. If you host on GitHub Pages, commit css/output.css because Pages does not run npm.

npm run dev
npm run build

How Tailwind Works

Each class does one small job. You build the design by adding classes in the HTML instead of writing a new CSS rule. When you build, Tailwind reads your files as plain text, finds the class names, and writes CSS for only those classes.

The same button in CSS and in Tailwind

.button {
  padding: 8px 16px;
  border-radius: 8px;
  background-color: #2563eb;
  color: white;
  font-weight: 600;
}

.button:hover {
  background-color: #1d4ed8;
}
  
<button class="rounded-lg bg-blue-600 px-4 py-2 font-semibold text-white hover:bg-blue-700">Save</button>

How to read a class

md:hover:bg-blue-600/50
|  |     |  |    |   |
|  |     |  |    |   +-- opacity: 50%
|  |     |  |    +------ shade: 50 is lightest, 950 is darkest
|  |     |  +----------- color name
|  |     +-------------- what it styles: bg is background
|  +-------------------- only while the mouse is over it
+----------------------- only at the md screen size and wider

Square brackets for any value

Use these when the design needs an exact value that is not in the scale. Use an underscore where you would type a space.

<!-- Exact size or color -->
<div class="top-[117px] w-[327px] bg-[#1a8468] text-[15px]"></div>

<!-- An underscore means a space -->
<div class="grid grid-cols-[1fr_2fr] gap-4"></div>
<div class="h-[calc(100dvh-4rem)]"></div>

<!-- Background image -->
<div class="bg-[url(/images/hero.jpg)] bg-cover bg-center"></div>

<!-- Any CSS property Tailwind has no class for -->
<div class="[clip-path:circle(50%)] [writing-mode:vertical-rl]"></div>

<!-- Round brackets read a CSS variable -->
<div class="bg-(--brand) text-(--ink)"></div>

<!-- Style every li from the ul -->
<ul class="[&>li]:py-2 [&>li:first-child]:pt-0">
  <li>One</li>
  <li>Two</li>
</ul>

<!-- A ! at the end forces the class to win -->
<p class="text-red-700!">This beats other text colors</p>

Full class names only

This is the most common Tailwind mistake. Tailwind reads your files as text, so it never runs your code and never sees a class that is pieced together.

// Wrong. No CSS gets made for this.
const wrong = `bg-${color}-600`;

// Right. Every full class name is in the file.
const colors = {
  blue: "bg-blue-600 hover:bg-blue-700",
  green: "bg-green-700 hover:bg-green-800",
  red: "bg-red-600 hover:bg-red-700",
};

const right = colors[color];

A color that comes from your database

Tailwind cannot know this color when it builds, so use a style prop for values that come from a user or the database.

<span className="rounded-full px-3 py-1 text-sm" style={{ backgroundColor: item.color }}>
  {item.name}
</span>

Tell Tailwind where to look

Tailwind finds your files on its own and skips anything in .gitignore. Add these lines when your classes live somewhere else, such as a server views folder.

@import "tailwindcss";

/* Also scan these folders */
@source "../views";
@source "../../shared/components";

/* Never scan this folder */
@source not "../legacy";

/* Always build these classes, even if no file uses them */
@source inline("bg-{red,green,blue}-{100,600}");

Rules to follow on every page

  • Use real tags: header, nav, main, section, footer, and button for anything you click that is not a link.
  • Use one h1 on a page, and do not skip heading levels.
  • Give every input a label. A placeholder is not a label.
  • Give every photo an alt. Use alt="" for a photo that is only decoration.
  • Give a button with only an icon an aria-label.
  • Do not use outline-none with nothing in its place. Keyboard users need to see where they are.
  • On a white page, use text-gray-500 or darker for text. White text needs a 600 shade or darker behind it.
