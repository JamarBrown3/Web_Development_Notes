What Changes When You Switch

Switching databases has two jobs: moving the data, and rewriting the server code that talks to the database. If your API keeps sending the same JSON, React does not change at all. The examples use a users collection and a posts collection, where each post has an author.

What maps to what

MongoDB                         PostgreSQL
collection                      table
document                        row
_id (ObjectId, 24 characters)   id SERIAL (1, 2, 3...)
ref: "User"                     REFERENCES users(id)
[String] array                  TEXT[] column
list of objects inside a doc    a separate child table
object inside a doc             flat columns, or JSONB
missing field                   NULL, or a DEFAULT
createdAt (camelCase)           created_at (snake_case)
populate()                      JOIN
pre("validate") rule            CHECK constraint, or validate in code

Steps For Either Direction

  • Back up the database you are moving away from.
  • Turn off saving on the live site, or pick a quiet time, so nothing new is missed.
  • Build the new tables or models.
  • Add both sets of values to server/.env so the script can reach both databases.
  • Run the migration script. It is safe to run again if it stops partway.
  • Compare the counts, then try some real records.
  • Swap the controllers and test every route.
  • Deploy with the new settings. Keep the old database untouched for a few weeks. Going back only means putting the old settings back.

MongoDB To PostgreSQL

Back up MongoDB

These tools come with mongodb-database-tools. The folder holds your real data, so keep it out of Git.

mongodump --uri="mongodb+srv://your_user:your_password@your_cluster.mongodb.net/my_project" --out=backup-mongo

Restore the MongoDB backup if needed

mongorestore --uri="mongodb+srv://your_user:your_password@your_cluster.mongodb.net" backup-mongo

Create the Postgres tables

Save this as server/config/schema.sql. The mongo_id column remembers which document each row came from, which is what makes the script safe to run twice. You can drop it after the move.

CREATE TABLE IF NOT EXISTS users (
  id SERIAL PRIMARY KEY,
  mongo_id CHAR(24) UNIQUE,
  username VARCHAR(35) NOT NULL UNIQUE,
  email VARCHAR(254) NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  role VARCHAR(20) NOT NULL DEFAULT 'user',
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS posts (
  id SERIAL PRIMARY KEY,
  mongo_id CHAR(24) UNIQUE,
  author_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(400) NOT NULL,
  body TEXT NOT NULL,
  tags TEXT[] NOT NULL DEFAULT '{}',
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS posts_author_index ON posts (author_id);

Run the schema file

psql "postgresql://your_user:your_password@your_host/your_database" -f config/schema.sql

server/scripts/mongoToPostgres.js

  • It reads the raw collections, so schema rules like select: false cannot hide the password hashes.
  • Password hashes move as plain text, so users keep their passwords.
  • Users go first so each post can look up its new author id in the Map.
  • MongoDB never checks that a ref is real, so a post with a deleted author gets skipped and reported.
  • Everything runs in one transaction. If one row fails, nothing is saved.
  • ON CONFLICT updates the row that is already there, so running it again does not duplicate anything.
import "dotenv/config";
import mongoose from "mongoose";
import pg from "pg";

const isLocal = ["localhost", "127.0.0.1"].includes(process.env.PGHOST);

const pool = new pg.Pool({
  user: process.env.PGUSER,
  password: process.env.PGPASSWORD,
  host: process.env.PGHOST,
  port: process.env.PGPORT,
  database: process.env.PGDATABASE,
  ssl: isLocal ? false : { rejectUnauthorized: false },
});

const copyUsers = async (mongo, client) => {
  const newIds = new Map(); // Mongo _id text -> new Postgres id

  for await (const user of mongo.collection("users").find()) {
    const results = await client.query(
      `INSERT INTO users (mongo_id, username, email, password_hash, role, created_at, updated_at)
      VALUES ($1, $2, $3, $4, $5, $6, $7)
      ON CONFLICT (mongo_id) DO UPDATE SET
        username = EXCLUDED.username,
        email = EXCLUDED.email,
        password_hash = EXCLUDED.password_hash,
        role = EXCLUDED.role,
        updated_at = EXCLUDED.updated_at
      RETURNING id`,
      [
        user._id.toString(),
        user.username,
        user.email,
        user.passwordHash,
        user.role ?? "user",
        user.createdAt ?? new Date(),
        user.updatedAt ?? new Date(),
      ],
    );

    newIds.set(user._id.toString(), results.rows[0].id);
  }

  return newIds;
};

const copyPosts = async (mongo, client, userIds) => {
  let saved = 0;
  let skipped = 0;

  for await (const post of mongo.collection("posts").find()) {
    const authorId = userIds.get(post.authorId?.toString());

    if (!authorId) {
      console.warn(`⚠️ Skipped post ${post._id}: its author does not exist.`);
      skipped += 1;
      continue;
    }

    await client.query(
      `INSERT INTO posts (mongo_id, author_id, title, body, tags, created_at, updated_at)
      VALUES ($1, $2, $3, $4, $5, $6, $7)
      ON CONFLICT (mongo_id) DO UPDATE SET
        author_id = EXCLUDED.author_id,
        title = EXCLUDED.title,
        body = EXCLUDED.body,
        tags = EXCLUDED.tags,
        updated_at = EXCLUDED.updated_at`,
      [
        post._id.toString(),
        authorId,
        post.title,
        post.body,
        post.tags ?? [],
        post.createdAt ?? new Date(),
        post.updatedAt ?? new Date(),
      ],
    );

    saved += 1;
  }

  return { saved, skipped };
};

const client = await pool.connect();

try {
  await mongoose.connect(process.env.MONGODB_URI, { dbName: process.env.MONGODB_DB_NAME });
  const mongo = mongoose.connection.db;

  await client.query("BEGIN");

  const userIds = await copyUsers(mongo, client);
  const posts = await copyPosts(mongo, client, userIds);

  await client.query("COMMIT");

  console.log(`✅ Copied ${userIds.size} users and ${posts.saved} posts. Skipped ${posts.skipped} posts.`);
} catch (error) {
  await client.query("ROLLBACK");
  console.error("⚠️ Nothing was saved. Migration failed:", error.message);
  process.exitCode = 1;
} finally {
  client.release();
  await pool.end();
  await mongoose.disconnect();
}

PostgreSQL To MongoDB

Back up Postgres

The file holds your real data, so keep it out of Git.

pg_dump "postgresql://your_user:your_password@your_host/your_database" -f backup-postgres.sql

Restore the Postgres backup if needed

psql "postgresql://your_user:your_password@your_host/your_database" -f backup-postgres.sql

Add the models

Use the schema examples on the MongoDB page. The Rev User model needs fields like status and sessionVersion, so set those in the script too. Add this field to each model. It remembers which row each document came from.

legacyId: { type: Number, unique: true, sparse: true },

server/scripts/postgresToMongo.js

  • It writes through the raw collection, so it can keep the original dates and password hashes. That also skips schema rules and defaults, so the script sets the defaults itself.
  • Users go first. MongoDB makes each new _id, and the Map gives each post its new author id.
  • Postgres sends NUMERIC, BIGINT, and COUNT values as text. Wrap those in Number() if you add them.
  • upsert updates a document that is already there, so running it again does not duplicate anything.
  • There is no transaction. If it stops partway, fix the problem and run it again.
import "dotenv/config";
import mongoose from "mongoose";
import pg from "pg";

const isLocal = ["localhost", "127.0.0.1"].includes(process.env.PGHOST);

const pool = new pg.Pool({
  user: process.env.PGUSER,
  password: process.env.PGPASSWORD,
  host: process.env.PGHOST,
  port: process.env.PGPORT,
  database: process.env.PGDATABASE,
  ssl: isLocal ? false : { rejectUnauthorized: false },
});

// Add or update every document in one request. Mongo rejects an empty list.
const saveAll = async (collection, documents) => {
  if (documents.length === 0) return;

  await collection.bulkWrite(
    documents.map((document) => ({
      updateOne: {
        filter: { legacyId: document.legacyId },
        update: { $set: document },
        upsert: true,
      },
    })),
  );
};

// Postgres id -> new Mongo _id
const readNewIds = async (collection) => {
  const saved = await collection.find({}, { projection: { legacyId: 1 } }).toArray();

  return new Map(saved.map((document) => [document.legacyId, document._id]));
};

const copyUsers = async (mongo) => {
  const collection = mongo.collection("users");
  const { rows } = await pool.query("SELECT * FROM users ORDER BY id");

  await collection.createIndex({ legacyId: 1 }, { unique: true, sparse: true });

  await saveAll(
    collection,
    rows.map((row) => ({
      legacyId: row.id,
      username: row.username,
      email: row.email,
      passwordHash: row.password_hash,
      role: row.role,
      status: "active",
      sessionVersion: 0,
      createdAt: row.created_at,
      updatedAt: row.updated_at,
    })),
  );

  return readNewIds(collection);
};

const copyPosts = async (mongo, userIds) => {
  const collection = mongo.collection("posts");
  const { rows } = await pool.query("SELECT * FROM posts ORDER BY id");

  await collection.createIndex({ legacyId: 1 }, { unique: true, sparse: true });

  await saveAll(
    collection,
    rows.map((row) => ({
      legacyId: row.id,
      authorId: userIds.get(row.author_id),
      title: row.title,
      body: row.body,
      tags: row.tags,
      createdAt: row.created_at,
      updatedAt: row.updated_at,
    })),
  );

  return rows.length;
};

try {
  await mongoose.connect(process.env.MONGODB_URI, { dbName: process.env.MONGODB_DB_NAME });
  const mongo = mongoose.connection.db;

  const userIds = await copyUsers(mongo);
  const postCount = await copyPosts(mongo, userIds);

  console.log(`✅ Copied ${userIds.size} users and ${postCount} posts.`);
} catch (error) {
  console.error("⚠️ Migration failed. Fix the problem and run it again:", error.message);
  process.exitCode = 1;
} finally {
  await pool.end();
  await mongoose.disconnect();
}

Swap The Server Code

Only the controllers and database config change. Keep the JSON the same in both versions and the routes and React stay as they are. The id in each URL does change, so old saved links stop working.

The same function in Postgres

AS "createdAt" and AS "authorName" keep the JSON the same as the Mongo version.

import { pool } from "../config/database.js";

const getPosts = async (req, res) => {
  const results = await pool.query(
    `SELECT p.id, p.title, p.body, p.tags,
            p.created_at AS "createdAt",
            u.username AS "authorName"
     FROM posts AS p
     JOIN users AS u ON u.id = p.author_id
     ORDER BY p.created_at DESC, p.id DESC
     LIMIT 20`,
  );

  res.status(200).json(results.rows);
};

export default { getPosts };

The same function in MongoDB

import Post from "../models/Post.js";

const getPosts = async (req, res) => {
  const posts = await Post.find({})
    .sort({ createdAt: -1, _id: -1 })
    .limit(20)
    .populate("authorId", "username");

  res.status(200).json(
    posts.map((post) => ({
      id: post._id,
      title: post.title,
      body: post.body,
      tags: post.tags,
      createdAt: post.createdAt,
      authorName: post.authorId?.username,
    })),
  );
};

export default { getPosts };

Each operation side by side

Job          PostgreSQL                                  MongoDB
Find all     pool.query("SELECT * FROM items")           Item.find({})
Find one     pool.query("... WHERE id = $1", [id])       Item.findById(id)
Result       results.rows, results.rows[0]               the documents themselves
Not found    results.rows.length === 0                   item === null
Create       INSERT ... RETURNING *                      Item.create(fields)
Update       UPDATE ... WHERE id = $1 RETURNING *        load it, change it, item.save()
Delete       DELETE ... WHERE id = $1 RETURNING *        item.deleteOne()
Check id     readId, on the Postgres page                readObjectId, on the MongoDB page
Bad input    validate in the controller, CHECK           schema rules and validate in code
Duplicate    error.code === "23505"                      error.code === 11000
Join         JOIN                                        populate()
Transaction  client BEGIN, COMMIT, ROLLBACK              session.withTransaction()

Handle a duplicate value after switching

The error code changes between databases, so check every place you catch a duplicate.

// Postgres
if (error.code === "23505") {
  return res.status(409).json({ error: "That value is already taken." });
}

// MongoDB
if (error.code === 11000) {
  return res.status(409).json({ error: "That value is already taken." });
}

Login And Security After Switching

  • Argon2id password hashes move as text, so passwords keep working. passwords.js does not change.
  • Sessions do not move. Everyone signs in again after the switch.
  • Change these Rev files for Postgres: models, config/database.js, databaseAccess.js, authService.js, accountLoginLimit.js, and the session store in auth.js. In the other direction, use the Rev files as they are.
  • mongooseSecurity.js protects MongoDB queries only. In Postgres, the $1 placeholders do that job, so never build SQL from strings.
  • Give the new database user the least power it needs, the same as the readWrite rule on the Security page.
