What Is Postgres

Postgres stores data in tables with rows and columns, and every column has a set type. You talk to it with SQL. Tables connect to each other through ids. The .env file for Postgres is on the Setup page.

Project Setup

Install the package

Run this from the folder that has your server package.json.

npm install pg

Local Postgres on a Mac

Use this when you want a database on your computer instead of a hosted one. A Homebrew install uses your Mac username with no password.

brew services start postgresql@14
createdb my_project
psql my_project

Pro-Tip: postgresql@14 is the version from my install. Run brew list | grep postgresql to see the name of yours, and use that name in the first line.

server/config/database.js

The pool keeps a few open connections and hands one to each query. Hosted databases like Render need SSL, and local ones do not. rejectUnauthorized: false still encrypts the connection, but it skips checking the host's certificate, so this is a class project setting.

// Reads .env into process.env. It is here as well as in server.js,
// because reset.js runs this file without server.js.
import "dotenv/config";
import pg from "pg";

// A database on your own computer does not use SSL. A hosted one does.
const isLocal = ["localhost", "127.0.0.1"].includes(process.env.PGHOST);

// Every value comes from server/.env.
const config = {
  user: process.env.PGUSER,
  password: process.env.PGPASSWORD,
  host: process.env.PGHOST,
  port: process.env.PGPORT,
  database: process.env.PGDATABASE,
  // Encrypt the connection when the database is hosted.
  ssl: isLocal ? false : { rejectUnauthorized: false },
};

// A pool keeps a few connections open and reuses them for every query.
export const pool = new pg.Pool(config);

Pro-Tip: If you see ECONNREFUSED 127.0.0.1:5432 while using a hosted database, .env did not load. When PGHOST is empty, pg tries a database on your own computer instead.

  if (error) throw error; // e.g. the port is already in use
  console.log(`🚀 Server listening on http://localhost:${PORT}`);
});

Create And Seed One Table

reset.js deletes the table, builds it again, and fills it with your starter data. Only run it by hand with npm run reset. Never add it to your start script, because every restart would delete everything users saved.

server/data/items.js

// Starter data. There is no id, because the database makes one for each row.
const itemData = [
  {
    title: "First Item",
    description: "This is the first item.",
    image: "https://picsum.photos/id/10/400/300",
  },
  {
    title: "Second Item",
    description: "This is the second item.",
    image: "https://picsum.photos/id/20/400/300",
  },
];

export default itemData;

server/config/reset.js

import "dotenv/config";
import { pool } from "./database.js";
import itemData from "../data/items.js";

// Step 1: delete the old table and make a new empty one.
const createTables = async () => {
  // SERIAL makes the id count up by itself. TIMESTAMPTZ saves the date and time.
  const createTableQuery = `
    DROP TABLE IF EXISTS items;

    CREATE TABLE items (
      id SERIAL PRIMARY KEY,
      title VARCHAR(255) NOT NULL,
      description TEXT NOT NULL DEFAULT '',
      image TEXT NOT NULL DEFAULT '',
      created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
    );
  `;

  await pool.query(createTableQuery);
  console.log("🎉 Items table created.");
};

// Step 2: copy the starter data into the table.
const seedTables = async () => {
  // $1, $2, and $3 are placeholders. The database fills them in safely.
  const insertQuery = `
    INSERT INTO items (title, description, image)
    VALUES ($1, $2, $3);
  `;

  for (const item of itemData) {
    // The order here has to match $1, $2, $3.
    const values = [item.title, item.description, item.image];

    await pool.query(insertQuery, values);
    console.log(`✅ ${item.title} added successfully`);
  }
};

// Run the two steps in order.
try {
  await createTables();
  await seedTables();
  console.log(`🎉 Finished! Saved ${itemData.length} items.`);
} catch (error) {
  console.error("⚠️ Reset failed:", error.message);
  // Tell the terminal that the script failed.
  process.exitCode = 1;
} finally {
  // Always close the pool, or the script never gives the prompt back.
  await pool.end();
}

Pro-Tip: This deletes the items table in whichever database .env points at. Check PGHOST and PGDATABASE before you run it, so you never reset a live site by mistake.

Full CRUD Controller

server/controllers/items.js

The $1 placeholders keep user input separate from the SQL, which is what stops SQL injection. RETURNING * sends back the saved row. Each route also checks the id first and answers 404 when no row matched. The update replaces every field, so send them all, which the edit form on the React page does. This uses the routes file from the Node page.

import { pool } from "../config/database.js";

// Validate IDs before querying PostgreSQL.
const readId = (value) => {
  // Only digits are allowed, so text such as abc or 1.5 is refused.
  if (!/^[0-9]+$/.test(String(value))) return null;

  const id = Number(value);

  // 2147483647 is the biggest number an INTEGER column can hold.
  return Number.isInteger(id) && id > 0 && id <= 2147483647 ? id : null;
};

// Return an error message, or an empty string when everything is valid.
const validateItem = (item) => {
  if (!item || typeof item !== "object" || Array.isArray(item)) {
    return "Item information is required.";
  }

  if (
    typeof item.title !== "string" ||
    !item.title.trim() ||
    item.title.trim().length > 255
  ) {
    return "Enter a title between 1 and 255 characters.";
  }

  return "";
};

// Match the order of the SQL placeholders.
const itemValues = (item) => [
  item.title.trim(),
  String(item.description ?? "").trim(),
  String(item.image ?? "").trim(),
];

// Log the real error, but never send database details to the browser.
const serverError = (res, error) => {
  console.error("Items database error:", error);

  return res.status(500).json({
    error: "Unable to complete the request. Please try again.",
  });
};

// GET /api/items
const getItems = async (req, res) => {
  try {
    const results = await pool.query("SELECT * FROM items ORDER BY id ASC");

    return res.status(200).json(results.rows);
  } catch (error) {
    return serverError(res, error);
  }
};

// GET /api/items/:id
const getItemById = async (req, res) => {
  const id = readId(req.params.id);

  if (id === null) {
    return res.status(400).json({ error: "Invalid item ID." });
  }

  try {
    const results = await pool.query("SELECT * FROM items WHERE id = $1", [id]);

    if (results.rows.length === 0) {
      return res.status(404).json({ error: "Item not found." });
    }

    return res.status(200).json(results.rows[0]);
  } catch (error) {
    return serverError(res, error);
  }
};

// POST /api/items
const createItem = async (req, res) => {
  const validationError = validateItem(req.body);

  if (validationError) {
    return res.status(400).json({ error: validationError });
  }

  try {
    // RETURNING * sends back the new row, with the id the database made.
    const results = await pool.query(
      `INSERT INTO items (title, description, image)
      VALUES ($1, $2, $3)
      RETURNING *`,
      itemValues(req.body),
    );

    return res.status(201).json(results.rows[0]);
  } catch (error) {
    return serverError(res, error);
  }
};

// PUT or PATCH /api/items/:id. It replaces every field, so send them all.
const updateItem = async (req, res) => {
  const id = readId(req.params.id);

  if (id === null) {
    return res.status(400).json({ error: "Invalid item ID." });
  }

  const validationError = validateItem(req.body);

  if (validationError) {
    return res.status(400).json({ error: validationError });
  }

  try {
    const results = await pool.query(
      `UPDATE items SET
        title = $1,
        description = $2,
        image = $3
      WHERE id = $4
      RETURNING *`,
      // The three fields fill $1 to $3, and the id fills $4.
      [...itemValues(req.body), id],
    );

    if (results.rows.length === 0) {
      return res.status(404).json({ error: "Item not found." });
    }

    return res.status(200).json(results.rows[0]);
  } catch (error) {
    return serverError(res, error);
  }
};

// DELETE /api/items/:id
const deleteItem = async (req, res) => {
  const id = readId(req.params.id);

  if (id === null) {
    return res.status(400).json({ error: "Invalid item ID." });
  }

  try {
    // RETURNING * sends back the row that was deleted.
    const results = await pool.query(
      "DELETE FROM items WHERE id = $1 RETURNING *",
      [id],
    );

    if (results.rows.length === 0) {
      return res.status(404).json({ error: "Item not found." });
    }

    return res.status(200).json(results.rows[0]);
  } catch (error) {
    return serverError(res, error);
  }
};

// The routes file uses these names, such as ItemsController.getItems.
export default {
  getItems,
  getItemById,
  createItem,
  updateItem,
  deleteItem,
};

Pro-Tip: This controller catches its own errors with try and catch, so it works on Express 4 and Express 5. The controller on the Node page throws instead, and that one needs Express 5.

server/config/reset.js with a transaction

BEGIN and COMMIT make the whole reset count as one step. If anything fails, ROLLBACK puts the database back the way it was. A transaction has to use one client from the pool, not pool.query.

import "dotenv/config";
import { pool } from "./database.js";
import locationData from "../data/locations.js";
import eventData from "../data/events.js";

// The child table (events) is dropped first, because it points at locations.
const createTables = async (client) => {
  // REFERENCES locations(id) makes location_id a foreign key.
  // ON DELETE CASCADE deletes the events of a location when the location is deleted.
  const createTableQuery = `
    DROP TABLE IF EXISTS events;
    DROP TABLE IF EXISTS locations;

    CREATE TABLE locations (
      id SERIAL PRIMARY KEY,
      name VARCHAR(255) NOT NULL UNIQUE,
      description TEXT NOT NULL,
      image TEXT NOT NULL
    );

    CREATE TABLE events (
      id SERIAL PRIMARY KEY,
      location_id INTEGER NOT NULL REFERENCES locations(id) ON DELETE CASCADE,
      title VARCHAR(255) NOT NULL,
      description TEXT NOT NULL,
      starts_at TIMESTAMPTZ NOT NULL
    );
  `;

  await client.query(createTableQuery);
  console.log("🎉 Locations and events tables created.");
};

const seedTables = async (client) => {
  // Save each new location's id so the events can point at it.
  const locationIds = new Map();

  // Parents go first, so their ids exist before the events need them.
  for (const location of locationData) {
    // RETURNING id sends back the id the database just made.
    const results = await client.query(
      `INSERT INTO locations (name, description, image)
      VALUES ($1, $2, $3)
      RETURNING id;`,
      [location.name, location.description, location.image],
    );

    locationIds.set(location.name, results.rows[0].id);
  }

  // Then the children. Each event looks up its location id by name.
  for (const event of eventData) {
    const locationId = locationIds.get(event.locationName);

    if (locationId === undefined) {
      throw new Error(`Unknown location "${event.locationName}" for event "${event.title}".`);
    }

    await client.query(
      `INSERT INTO events (location_id, title, description, starts_at)
      VALUES ($1, $2, $3, $4);`,
      [locationId, event.title, event.description, event.starts_at],
    );
  }
};

// One client for the whole transaction. pool.query could use
// a different connection for each line.
const resetDatabase = async () => {
  const client = await pool.connect();

  try {
    // BEGIN starts the transaction. Nothing is final until COMMIT.
    await client.query("BEGIN");

    await createTables(client);
    await seedTables(client);

    await client.query("COMMIT");

    console.log(`✅ Saved ${locationData.length} locations and ${eventData.length} events.`);
  } catch (error) {
    // Something failed, so undo everything since BEGIN.
    await client.query("ROLLBACK");
    throw error;
  } finally {
    // Give the client back to the pool, even after an error.
    client.release();
  }
};

try {
  await resetDatabase();
} catch (error) {
  console.error("⚠️ Reset failed:", error.message);
  process.exitCode = 1;
} finally {
  // Always close the pool, or the script never gives the prompt back.
  await pool.end();
}

Get events with their location using JOIN

Save this as server/controllers/events.js. The routes file that goes with it is right below.

import { pool } from "../config/database.js";

// GET /api/events sends back every event with the name and image of its location.
const getEvents = async (req, res) => {
  try {
    // JOIN puts each event together with its location row.
    // AS gives the location columns names that do not clash with the event columns.
    const results = await pool.query(
      `SELECT e.id, e.location_id, e.title, e.description, e.starts_at,
              l.name AS location_name, l.image AS location_image
       FROM events AS e
       JOIN locations AS l ON l.id = e.location_id
       ORDER BY e.starts_at, e.id`,
    );

    res.status(200).json(results.rows);
  } catch (error) {
    console.error("Error loading events:", error.message);
    res.status(500).json({ error: "Unable to load events." });
  }
};

// GET /api/events/location/:locationId sends back the events for one location.
const getEventsByLocation = async (req, res) => {
  // req.params values are always text, so turn it into a number and check it.
  const locationId = Number(req.params.locationId);

  if (!Number.isInteger(locationId) || locationId < 1 || locationId > 2147483647) {
    return res.status(400).json({ error: "Invalid location ID." });
  }

  try {
    // Check that the location exists, so a wrong id gets a 404 and not an empty list.
    const locationResults = await pool.query(
      "SELECT id FROM locations WHERE id = $1",
      [locationId],
    );

    if (locationResults.rows.length === 0) {
      return res.status(404).json({ error: "Location not found." });
    }

    const results = await pool.query(
      `SELECT id, location_id, title, description, starts_at
       FROM events
       WHERE location_id = $1
       ORDER BY starts_at, id`,
      [locationId],
    );

    res.status(200).json(results.rows);
  } catch (error) {
    console.error("Error loading events:", error.message);
    res.status(500).json({ error: "Unable to load events for this location." });
  }
};

// The routes file uses these names, such as EventsController.getEvents.
export default { getEvents, getEventsByLocation };

Many to many with a join table

One student can take many classes, and one class has many students. The middle table stores one row for each pairing.

-- Two normal tables.
CREATE TABLE students (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL
);

CREATE TABLE classes (
  id SERIAL PRIMARY KEY,
  title VARCHAR(255) NOT NULL
);

-- The join table. Each row means one student is in one class.
-- The two ids together are the primary key, so the same pairing cannot be saved twice.
CREATE TABLE enrollments (
  student_id INTEGER NOT NULL REFERENCES students(id) ON DELETE CASCADE,
  class_id INTEGER NOT NULL REFERENCES classes(id) ON DELETE CASCADE,
  PRIMARY KEY (student_id, class_id)
);

-- Every student in class 1, with the title of the class.
SELECT s.name, c.title
FROM enrollments AS e
JOIN students AS s ON s.id = e.student_id
JOIN classes AS c ON c.id = e.class_id
WHERE c.id = 1;

SQL Reference

Column types and rules

CREATE TABLE examples (
  id SERIAL PRIMARY KEY,                       -- auto-increasing id
  name VARCHAR(255) NOT NULL,                  -- short text, required
  email VARCHAR(254) NOT NULL UNIQUE,          -- no duplicates allowed
  bio TEXT,                                    -- long text, optional
  age INTEGER CHECK (age >= 0),                -- whole number with a rule
  price_cents INTEGER NOT NULL DEFAULT 0,      -- store money as whole cents
  rating NUMERIC(3, 1),                        -- exact decimal such as 9.5
  is_active BOOLEAN NOT NULL DEFAULT TRUE,     -- true or false
  tags TEXT[],                                 -- a list of text
  settings JSONB,                              -- JSON data
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW() -- date and time
);

Reading rows

SELECT * FROM items;                                -- every row and every column
SELECT id, title FROM items WHERE id = 1;           -- two columns from one row
SELECT * FROM items WHERE title ILIKE '%game%';     -- search, ignoring capitals
SELECT * FROM items ORDER BY created_at DESC;       -- newest first
SELECT * FROM items ORDER BY id LIMIT 10 OFFSET 20; -- page 3 of 10 per page
SELECT COUNT(*) FROM items;                         -- how many rows

Adding, changing, and deleting rows

Always include WHERE on UPDATE and DELETE. Without it, every row in the table changes.

INSERT INTO items (title, description) VALUES ('New item', 'Hello'); -- add a row
UPDATE items SET title = 'Changed' WHERE id = 1;                     -- change one row
DELETE FROM items WHERE id = 1;                                      -- remove one row

Pro-Tip: Text in SQL goes in single quotes. Double quotes mean a column name. Before an UPDATE or DELETE, run a SELECT with the same WHERE to see which rows it will hit.

Group and count

-- How many events each location has, biggest first.
SELECT location_id, COUNT(*) AS total
FROM events
GROUP BY location_id
-- HAVING filters the groups. WHERE filters the rows before they are grouped.
HAVING COUNT(*) > 1
ORDER BY total DESC;

Change a table that has data in it

ALTER TABLE items ADD COLUMN price_cents INTEGER NOT NULL DEFAULT 0; -- add a column, and old rows get 0
ALTER TABLE items RENAME COLUMN price_cents TO price;                -- rename it
ALTER TABLE items DROP COLUMN price;                                 -- delete the column and its data
CREATE INDEX items_title_index ON items (title);                     -- make searches on title faster

Pro-Tip: DROP COLUMN deletes the data in that column for good. Back up first with pg_dump, which is on the Switch Databases page.

Search with user input the safe way

Put the % signs in the value, not in the SQL string. This is a whole controller file. Save it as server/controllers/search.js, or move the function into controllers/items.js and add it to the export list there.

import { pool } from "../config/database.js";

// GET /api/items/search?search=game
const searchItems = async (req, res) => {
  // req.query values are text or missing. String() also covers ?search=a&search=b.
  const search = String(req.query.search ?? "").trim();

  // A very long search is never a real one.
  if (search.length > 100) {
    return res.status(400).json({ error: "Search must be 100 characters or fewer." });
  }

  try {
    // The % signs go in the value, not in the SQL text. % means any characters.
    const results = await pool.query(
      "SELECT * FROM items WHERE title ILIKE $1 ORDER BY id LIMIT 50",
      [`%${search}%`],
    );

    return res.status(200).json(results.rows);
  } catch (error) {
    console.error("Items search error:", error);

    return res.status(500).json({
      error: "Unable to complete the request. Please try again.",
    });
  }
};

export default { searchItems };

// The route goes above "/:id" in routes/items.js, or /:id catches the word search:
// import SearchController from "../controllers/search.js";
// router.get("/search", SearchController.searchItems);

Pro-Tip: A % or _ that a visitor types also works as a wildcard inside ILIKE. That is harmless here, but a search for 50% matches more than they expect.

Never build SQL by joining strings

The DANGER line lets anyone run their own SQL through your form, so it is commented out here. The SAFE query under it is the one that runs.

import { pool } from "../config/database.js";

// POST /api/users/find with a body such as { "email": "sam@example.com" }
const findUserByEmail = async (req, res) => {
  const email = String(req.body?.email ?? "");

  // DANGER: SQL injection. The email becomes part of the SQL text, so sending
  // ' OR '1'='1 as the email would send back every user. Never write this:
  // pool.query(`SELECT * FROM users WHERE email = '${email}'`);

  try {
    // SAFE: the value travels separately from the SQL.
    const results = await pool.query(
      "SELECT id, email FROM users WHERE email = $1",
      [email],
    );

    if (results.rows.length === 0) {
      return res.status(404).json({ error: "User not found." });
    }

    return res.status(200).json(results.rows[0]);
  } catch (error) {
    console.error("Users database error:", error);

    return res.status(500).json({
      error: "Unable to complete the request. Please try again.",
    });
  }
};

export default { findUserByEmail };

Column names turn lowercase

Postgres lowers any name without quotes, so pricePoint becomes pricepoint. That caused my unearthed mismatch. Use snake_case names like price_point, and rename them for React with AS.

import { pool } from "../config/database.js";

// GET /api/gifts
const getGifts = async (req, res) => {
  try {
    // The column is price_point in the database. AS "pricePoint" renames it for React.
    // The double quotes keep the capital P. Without them Postgres sends pricepoint.
    const results = await pool.query(
      `SELECT id, price_point AS "pricePoint" FROM gifts ORDER BY id`,
    );

    return res.status(200).json(results.rows);
  } catch (error) {
    console.error("Gifts database error:", error);

    return res.status(500).json({
      error: "Unable to complete the request. Please try again.",
    });
  }
};

export default { getGifts };
