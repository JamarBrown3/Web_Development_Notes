Find A Bug Fast

Check in this order. Each step tells you which half of the app is broken before you touch any code.

1. Is the server running?   Look for 🚀 in the terminal. If you see "Completed running"
                             right after it, the server already stopped.
2. Does the proxy work?      Open http://localhost:5173/api/health
                             {"status":"ok"} = server and proxy are fine, the bug is in React.
                             502 or a blank page = the server is not running.
3. Does the data look right? Open http://localhost:3000/api/items and read the JSON.
                             Is it an array? Do the field names match what React reads?
4. Browser console           Red errors. The first one is the real one, the rest follow from it.
5. Network tab               Click the request. Check the status and the Response tab.
6. console.log the value     Right before the line that breaks: console.log(pizza)

Server And Proxy

502 Bad Gateway and "Unexpected end of JSON input"

I hit this. The 502 comes from the Vite proxy. It sent /api/items to port 3000 and nobody answered. No answer means no JSON, so response.json() throws "Unexpected end of JSON input". The second error is only a side effect of the first. The usual cause is running npm run dev inside client, which only starts Vite.

# ❌ only starts React
cd client && npm run dev

# ✅ starts React and Express together with concurrently
cd pizza-menu && npm run dev

# Check what is on each port
lsof -i :3000
lsof -i :5173

Pro-Tip: Do not paste this whole box into the terminal. It shows the wrong command and the right one side by side, so type only the one you need. A Mac terminal also does not skip a line that starts with # unless you run setopt interactive_comments first.

Right version: Setup page, Run React And Node Together

🚀 Server listening, then "Completed running"

I hit this. Another server already had port 3000. In Express 5, app.listen does not crash when the port is taken. It hands the error to your callback. If the callback ignores the error, it prints 🚀 anyway and Node exits because nothing is listening.

// ❌ prints success even when the port is taken
app.listen(PORT, () => {
  console.log(`🚀 Server listening on http://localhost:${PORT}`);
});

// ✅ shows the real error: EADDRINUSE
app.listen(PORT, (error) => {
  if (error) throw error; // e.g. the port is already in use
  console.log(`🚀 Server listening on http://localhost:${PORT}`);
});
  
# Find and stop whatever is on the port
lsof -ti :3000 | xargs kill

Right version: Node page, server/server.js. All three starters already have the fix.

Unexpected token '<', "<!doctype "... is not valid JSON

The request reached Vite instead of Express, and Vite answered with index.html. The < is the start of <!doctype html>. Either the proxy is missing from vite.config.js, or the fetch path does not start with /api.

// client/vite.config.js
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [react()],
  server: {
    // Any request that starts with /api is passed on to Express on port 3000.
    proxy: { "/api": "http://localhost:3000" },
  },
});
  
// ❌ no /api, so the proxy never sees it
fetch("/items");

// ✅ starts with /api, so the proxy passes it on to Express
fetch("/api/items");

Restart Vite after you change vite.config.js. It does not reload the config while it runs. Right version: React page, client/vite.config.js

Blocked by CORS policy

You fetched the full address http://localhost:3000/api/items from port 5173. The browser treats a different port as a different site and blocks it. Use the proxy and a short path, so the browser only ever talks to 5173.

// ❌ different port, so the browser blocks it
fetch("http://localhost:3000/api/items");

// ✅ goes through the Vite proxy
fetch("/api/items");

Right version: React page, client/vite.config.js

Fetching Data

useEffect(async () => ...)

I hit this. The function passed to useEffect cannot be async. React expects it to return nothing or a cleanup function, and an async function always returns a Promise. Put an async function inside the effect and call it.

// ❌
useEffect(async () => {
  const response = await fetch("/api/items");
}, []);

// ✅ async function inside, then call it
useEffect(() => {
  const fetchItems = async () => {
    const response = await fetch("/api/items");
    const data = await response.json();
    setItems(data);
  };

  fetchItems();
}, []);

Way to remember it: useEffect can't be async, so put an async function inside and call it. Right version: React page, Fetch data when the page loads

await fetch() not saved, then res is not defined

I hit this. await fetch() gives back a response, but only if you store it. Using a name that was never made gives "res is not defined".

// ❌
await fetch("/api/items");
const data = await res.json();

// ✅
const response = await fetch("/api/items");
const data = await response.json();

Not checking response.ok

fetch only throws when the network fails. A 404 or 500 still counts as success, so the error JSON from the server ends up in state. Then items.map breaks because { error: "..." } is not an array.

// ✅ check response.ok before you read the JSON
const response = await fetch("/api/items");

if (!response.ok) {
  throw new Error(`Request failed (${response.status}).`);
}

const data = await response.json();

Right version, with loading, error and the ignore flag: React page, Fetch data when the page loads

useEffect with no array fetches forever

With no dependency array, the effect runs after every redraw. The fetch sets state, setting state redraws, and the redraw runs the fetch again.

// ❌ runs after every redraw
useEffect(() => {
  fetchItems();
});

// ✅ runs once when the page loads
useEffect(() => {
  fetchItems();
}, []);

Right version: React page, The three dependency options

Fetch runs twice in development

Not a bug. StrictMode in main.jsx runs every effect twice in development to catch missing cleanup. It only runs once in the built site. Keep the ignore flag so the extra response is dropped.

useEffect(() => {
  // The cleanup at the bottom sets this to true.
  let ignore = false;

  const fetchItems = async () => {
    const response = await fetch("/api/items");
    const data = await response.json();
    // Skip the answer from the run that React threw away.
    if (!ignore) setItems(data);
  };

  fetchItems();
  // The cleanup. React runs it when the effect is thrown away.
  return () => {
    ignore = true;
  };
}, []);

Every fetch fix in one working component

The boxes above show each bug next to its fix. This is a whole file with every fix from this section in place, so you can copy it and run it. It reads item.title, so change that to a field your own data has.

// client/src/pages/Items.jsx
// Fix: hooks have to be imported in every file that uses them.
import { useEffect, useState } from "react";

function Items() {
  // Fix: a list starts as an empty array, so map never runs on undefined.
  const [items, setItems] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");

  // Fix: the function given to useEffect is not async.
  useEffect(() => {
    // Fix: StrictMode runs this twice in development. ignore drops the extra answer.
    let ignore = false;

    // Fix: the async function goes inside the effect.
    const fetchItems = async () => {
      try {
        // Fix: a short path that starts with /api, so the Vite proxy handles it.
        // Fix: save what fetch gives back.
        const response = await fetch("/api/items");

        // Fix: fetch does not throw on a 404 or a 500, so check it yourself.
        if (!response.ok) {
          throw new Error(`Request failed (${response.status}).`);
        }

        const data = await response.json();

        if (!ignore) setItems(data);
      } catch (caught) {
        // A failed request ends up here and not as a red error in the console.
        if (!ignore) setError(caught.message);
      } finally {
        if (!ignore) setLoading(false);
      }
    };

    fetchItems();

    // The cleanup. React runs it when the component leaves the page.
    return () => {
      ignore = true;
    };
    // Fix: the empty array means run once, when the page loads.
  }, []);

  if (loading) return <p>Loading...</p>;
  if (error) return <p>{error}</p>;

  return (
    <ul>
      {items.map((item) => (
        <li key={item.id}>{item.title}</li>
      ))}
    </ul>
  );
}

export default Items;

Props And Components

$undefined or blank cards: props not destructured

I hit this. React passes a component one object that holds every prop. With <Pizza pizza={pizza} /> the component gets { pizza: { name, price, ... } }. Without curly braces, the variable named pizza is that whole props object, so pizza.name is undefined and the price shows as $undefined.

// ❌ pizza is the whole props object
function Pizza(pizza) {
  return <span>${pizza.price}</span>; // $undefined
}

// ✅ pull the pizza key out of props
function Pizza({ pizza }) {
  return <span>${pizza.price}</span>;
}

// ✅ the same thing without destructuring
function Pizza(props) {
  return <span>${props.pizza.price}</span>;
}

Way to remember it: props always arrive as one object. Right version: React page, Components And Props

Field name typo gives undefined with no error

I hit this. pizza.photName instead of pizza.photoName. JavaScript does not warn about a missing key. It just gives undefined, so the image breaks quietly. Open /api/items and copy the field names from the real JSON.

// ❌
<img src={pizza.photName} alt={pizza.name} />

// ✅
<img src={pizza.photoName} alt={pizza.name} />

// Quick check: log the object and read the real keys
console.log(pizza);

useState is not defined

I hit this. Hooks have to be imported at the top of every file that uses them.

// ✅ at the top of every file that uses a hook
import { useState, useEffect } from "react";

Component name starts with a lowercase letter

JSX treats <pizza /> as an unknown HTML tag, so nothing shows and there is no clear error. Component names must start with a capital letter.

// ❌
function pizza() { ... }
<pizza />

// ✅
function Pizza() { ... }
<Pizza />

Default vs named import

The import has to match how the other file exports. A mismatch gives "does not provide an export named" or undefined.

// Default export: one per file, no braces when importing
export default Pizza;
import Pizza from "./components/Pizza.jsx";

// Named export: braces when importing, same exact name
export const Pizza = () => { ... };
import { Pizza } from "./components/Pizza.jsx";

Lists And map

map with curly braces and no return shows nothing

Parentheses return the JSX automatically. Curly braces start a function body, so you have to write return yourself, or map gives back a list of undefined.

// ❌ curly braces, no return, empty list
{pizzas.map((pizza) => {
  <Pizza key={pizza.id} pizza={pizza} />
})}

// ✅ parentheses return it for you
{pizzas.map((pizza) => (
  <Pizza key={pizza.id} pizza={pizza} />
))}

// ✅ curly braces with return
{pizzas.map((pizza) => {
  return <Pizza key={pizza.id} pizza={pizza} />;
})}

Right version: React page, Show a list with map

Each child in a list should have a unique "key" prop

The key goes on the outer element that map returns, not inside the component. Use an id from the data. The array index works only for a list that never changes order, gets filtered, or has items removed.

// ❌ no key
{pizzas.map((pizza) => <Pizza pizza={pizza} />)}

// ✅ id from the data
{pizzas.map((pizza) => <Pizza key={pizza.id} pizza={pizza} />)}

items.map is not a function

The value is not an array. Usually the server sent an object, like { items: [...] } or { error: "..." }. Open the API in the browser and look at the outer shape.

// Server sends { items: [...] }
const data = await response.json();
setItems(data.items);

// Server sent { error: "..." } because the request failed: check response.ok first

See Not checking response.ok.

Cannot read properties of undefined (reading 'map')

The first draw happens before the fetch finishes. If state starts as undefined, map runs on undefined. Start lists as an empty array.

// ❌
const [items, setItems] = useState();

// ✅
const [items, setItems] = useState([]);

// For one item that starts as null, check before reading it
const [item, setItem] = useState(null);
if (!item) return <p>Loading...</p>;

State

console.log shows the old value right after setState

Not a bug. setState schedules a redraw. The variable keeps its old value until the component runs again.

setCount(count + 1);
console.log(count); // still the old number

// When the new value depends on the old one, use the function form
setCount((current) => current + 1);

Changing the array or object directly does not redraw

React compares the old and new value. push and direct edits change the same array, so React sees no change. Always make a new array or object.

// ❌
items.push(newItem);
setItems(items);

// ✅ add
setItems((current) => [...current, newItem]);

// ✅ update one
setItems((current) => current.map((item) => (item.id === id ? { ...item, ...changes } : item)));

// ✅ remove one
setItems((current) => current.filter((item) => item.id !== id));

Right version: React page, Add, update, and remove in an array

Too many re-renders: calling the function in onClick

onClick={handleDelete(id)} runs the function while the page draws, not when it is clicked. If it sets state, that redraws, which runs it again.

// ❌ runs during the draw
<button onClick={handleDelete(pizza.id)}>Delete</button>

// ✅ runs on click
<button onClick={() => handleDelete(pizza.id)}>Delete</button>

// ✅ no arguments: pass the function itself
<button onClick={handleClick}>Click</button>

JSX

Objects are not valid as a React child

You put a whole object or the props object between tags. JSX can show strings, numbers and elements, not objects.

// ❌
<p>{pizza}</p>

// ✅ pick a field
<p>{pizza.name}</p>

// ✅ to look at the whole thing while debugging
<pre>{JSON.stringify(pizza, null, 2)}</pre>

A random 0 shows up on the page

With &&, React draws the left side when it is falsy. false shows nothing, but 0 is a number, so it shows 0.

// ❌ shows 0 when the list is empty
{items.length && <ItemList items={items} />}

// ✅
{items.length > 0 && <ItemList items={items} />}

HTML attributes that are different in JSX

class="card"            ->  className="card"
for="email"             ->  htmlFor="email"
style="color: red"      ->  style={{ color: "red" }}
onclick="go()"          ->  onClick={go}
<img> <br> <input>     ->  <img /> <br /> <input />
<!-- comment -->        ->  {/* comment */}

Adjacent JSX elements must be wrapped

A component returns one thing. Wrap siblings in a div or an empty fragment.

// ✅ <> and </> wrap the two siblings without adding a div
return (
  <>
    <h1>Pizza Menu</h1>
    <p>Fresh every day</p>
  </>
);

Props, lists, state, and JSX fixes in one working App.jsx

This is a whole file with the fixes from Props And Components, Lists And map, State, and JSX in place. Each comment that starts with Fix names the bug it avoids.

// client/src/App.jsx. It needs no server, so it runs in any new Vite project.
import { useState } from "react";

const starterPizzas = [
  { id: 1, name: "Focaccia", price: 6 },
  { id: 2, name: "Pizza Margherita", price: 10 },
];

// Fix: the name starts with a capital letter.
// Fix: { pizza, onDelete } pulls the props out of the one props object.
function Pizza({ pizza, onDelete }) {
  return (
    <li>
      {/* Fix: show fields from the object, not the whole object. */}
      <strong>{pizza.name}</strong> ${pizza.price}{" "}
      {/* Fix: the arrow function makes this run on click, not while the page draws. */}
      <button onClick={() => onDelete(pizza.id)}>Delete</button>
    </li>
  );
}

function App() {
  const [pizzas, setPizzas] = useState(starterPizzas);

  const handleAdd = () => {
    // Fix: build a new array. push changes the old one and React does not redraw.
    // Fix: the function form always gets the newest value.
    setPizzas((current) => [
      ...current,
      { id: Date.now(), name: "New Pizza", price: 12 },
    ]);
  };

  const handleDelete = (id) => {
    // filter gives back a new array without the one that was deleted.
    setPizzas((current) => current.filter((pizza) => pizza.id !== id));
  };

  return (
    // Fix: an empty fragment wraps the siblings, so the component returns one thing.
    <>
      <h1>Pizza Menu</h1>
      {/* Fix: there are no arguments, so pass the function itself. */}
      <button onClick={handleAdd}>Add a pizza</button>

      {/* Fix: > 0 gives true or false, so a 0 never shows on the page. */}
      {pizzas.length > 0 && (
        <ul>
          {/* Fix: parentheses return the JSX. The key is an id from the data. */}
          {pizzas.map((pizza) => (
            <Pizza key={pizza.id} pizza={pizza} onDelete={handleDelete} />
          ))}
        </ul>
      )}

      {pizzas.length === 0 && <p>No pizzas left.</p>}
    </>
  );
}

export default App;

Express Routes

GET /api/items/1 returns 404: the data has no id

I hit this. getItemById searches for item.id, but the pizza data had no id fields, so every lookup failed. Give every record an id. React keys need it too.

// server/data/items.js
const items = [
  { id: 1, name: "Focaccia", price: 6 },
  { id: 2, name: "Pizza Margherita", price: 10 },
];

Right version: Node page, Setup 2 server/data/items.js

req.params.id is always a string

"1" === 1 is false, so find never matches. Turn it into a number first.

// ❌
items.find((item) => item.id === req.params.id);

// ✅
items.find((item) => item.id === Number(req.params.id));

req.body is undefined

Two causes. The server is missing express.json(), or the fetch did not send the Content-Type header, so Express does not know the body is JSON.

// server/server.js, before the routes
app.use(express.json());
  
// client fetch
await fetch("/api/items", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(newItem),
});

Right version: React page, Talking To The Server and Node page, Middleware

A route like /new gets caught by /:id

Express checks routes from top to bottom. /:id matches anything, including "new". Put fixed paths above paths with params.

// ✅ fixed path first
router.get("/featured", ItemsController.getFeatured);
router.get("/:id", ItemsController.getItemById);

Request stays pending forever

The controller never sent a response. Every path through the function has to end in res.json, res.send, res.sendStatus, or a thrown error.

// ❌ found the item and never sent it
const getItemById = (req, res) => {
  const item = items.find((other) => other.id === Number(req.params.id));
};

// ✅
const getItemById = (req, res) => {
  const item = items.find((other) => other.id === Number(req.params.id));
  if (!item) throw new HttpError(404, "Item not found.");
  res.status(200).json(item);
};

Cannot set headers after they are sent

The code sent two responses. res.json does not stop the function, so add return to the early one.

// ❌ sends the 404, then keeps going and sends again
if (!item) res.status(404).json({ error: "Item not found." });
res.json(item);

// ✅
if (!item) return res.status(404).json({ error: "Item not found." });
res.json(item);

Every Express route fix in one working server.js

This is a whole file with every fix from this section in place. Each comment that starts with Fix names the bug it avoids.

// Runs on its own. Save it as server.js, then run: node server.js
import express from "express";

const app = express();

// Fix: every record has an id, and the id is a number.
const items = [
  { id: 1, name: "Focaccia", price: 6 },
  { id: 2, name: "Pizza Margherita", price: 10 },
];

// Fix: express.json() goes above the routes, or req.body is undefined.
app.use(express.json({ limit: "100kb" }));

app.get("/api/items", (req, res) => {
  res.status(200).json(items);
});

// Fix: the fixed path goes above /:id, or /:id catches the word featured.
app.get("/api/items/featured", (req, res) => {
  res.status(200).json(items[0]);
});

app.get("/api/items/:id", (req, res) => {
  // Fix: req.params.id is text, so turn it into a number before comparing.
  const item = items.find((other) => other.id === Number(req.params.id));

  // Fix: return stops the function, so only one response is sent.
  if (!item) return res.status(404).json({ error: "Item not found." });

  // Fix: every path through the function ends in a response.
  res.status(200).json(item);
});

app.post("/api/items", (req, res) => {
  // req.body is still undefined when the request did not send the JSON header.
  if (typeof req.body?.name !== "string") {
    return res.status(400).json({ error: "Name is required." });
  }

  const item = {
    id: items.length + 1,
    name: req.body.name,
    price: Number(req.body.price) || 0,
  };

  items.push(item);
  res.status(201).json(item);
});

// Fix: check the error, so a taken port shows EADDRINUSE and not a false 🚀.
app.listen(3000, (error) => {
  if (error) throw error;
  console.log("🚀 Server listening on http://localhost:3000");
});

Express 4: an error in an async route crashes or hangs

Express 5 sends errors from async routes to the error handler on its own. Express 4 does not, so old projects need try/catch and next(error). Check the express version in package.json before reusing code.

Right version: Node page, Errors In Express 4 And 5

Data, .env And Images

process.env.SOMETHING is undefined

The .env file is not being loaded, it is in the wrong folder, or the server was not restarted after the change. In pizza-menu, import "dotenv/config" is commented out at the top of server.js, so anything in a .env file is ignored. Only PORT works there, because it falls back to 3000.

// First line of server/server.js
import "dotenv/config";

In React, only variables that start with VITE_ reach the browser, read as import.meta.env.VITE_API_URL. Never put secrets in client/.env. Right version: Setup page, .env files

Images break on some pages

Files in client/public are served from the root of the site. A path with no leading slash is relative to the current URL, so "pizzas/focaccia.jpg" works on / but looks for /menu/pizzas/focaccia.jpg on /menu. Start public paths with a slash.

// ❌ breaks on nested routes
photoName: "pizzas/focaccia.jpg"

// ✅ always from the site root (client/public/pizzas/focaccia.jpg)
photoName: "/pizzas/focaccia.jpg"

Node: Cannot find module, but the file is there

With type module, Node needs the full file name, including .js. Vite lets you skip it in React, Node does not.

// ❌
import itemsRouter from "./routes/items";

// ✅
import itemsRouter from "./routes/items.js";
