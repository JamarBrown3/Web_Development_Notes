VS Code Terminal

Open the terminal in VS Code with Ctrl + ` (that key is above Tab). Every Terminal block on this page gets typed in there. Ctrl + C stops a running server.

Open a project folder from the terminal

cd ~/Documents/Node_Express_class
mkdir my-project
cd my-project
code .

Commands you use the most

pwd                # show the folder you are in
ls                 # list the files in this folder
ls -a              # also list hidden files such as .env
cd client          # go into the client folder
cd ..              # go back up one folder
mkdir server       # make a folder
touch server/.env  # make an empty file

Check that everything is installed

node -v
npm -v
git --version

Setup React With Vite

Run this from your project folder. It makes the client folder. When Vite asks a question, use the arrow keys and press Enter.

Make the React app

npm create vite@latest client -- --template react
cd client
npm install
npm install react-router-dom
npm run dev

The site opens at http://localhost:5173. Press Ctrl + C to stop it.

Remove the starter files you will not use

Run this after you paste in your own App.jsx from the React page, because the starter App.jsx uses these files.

rm src/App.css src/assets/react.svg src/assets/vite.svg src/assets/hero.png

Setup Node And Express

Run this from your project folder. It makes the server folder and adds the scripts.

Make the Express server

mkdir server
cd server
npm init -y
npm pkg set type=module
npm pkg set scripts.dev="nodemon server.js" scripts.start="node server.js"
npm install express cors dotenv
npm install --save-dev nodemon
mkdir config controllers routes data
touch server.js .env .env.example

Start the server

npm run dev

The starter server.js is on the Node page.

The parts of server/package.json that matter

{
  "name": "server",
  "version": "1.0.0",
  "type": "module",
  "main": "server.js",
  "scripts": {
    "dev": "nodemon server.js",
    "start": "node server.js"
  }
}

Run React And Node Together

This is the one package.json layout. Run these from the main project folder, and one command starts both the client and the server.

Add concurrently from the main project folder

npm init -y
npm pkg set type=module
npm install concurrently express dotenv react react-dom react-router-dom
npm install --save-dev vite @vitejs/plugin-react nodemon

package.json scripts in the main project folder

{
  "scripts": {
    "dev": "concurrently \"cd client && vite\" \"cd server && nodemon server\"",
    "reset": "cd server && node --require dotenv/config config/reset.js",
    "build": "cd client && vite build",
    "start": "cd server && node server"
  }
}

Start everything

npm run dev

Env Files

  • The .env file holds your passwords. It goes in the server folder and it never goes on GitHub.
  • There are no spaces around the = sign and no quotes are needed.
  • Copy the block you need, then replace the placeholder values with your real ones.
  • .env.example is the same file with the secret values left blank. That one is safe to commit.
  • Restart the server after you change .env, because it is only read at startup.

Load .env in the server

Put this line at the top of the first file that needs it. It looks for .env in the folder you started the server from.

import "dotenv/config";

server/config/env.js

This Rev version finds .env no matter which folder you start from, and it stops with a clear message when a value is missing or wrong.

// Resolve .env relative to this file, not the terminal's working directory.
// Existing deployment environment variables take precedence over .env.
import dotenv from "dotenv";
import { fileURLToPath } from "node:url";

dotenv.config({
  path: fileURLToPath(new URL("../.env", import.meta.url)),
  quiet: true,
});

// Read and validate the MongoDB connection settings.
// This does not connect to the MongoDB database yet.
export function getDatabaseConfig() {
  const uri = process.env.MONGODB_URI?.trim();
  const dbName = process.env.MONGODB_DB_NAME?.trim();

  // Accept either supported MongoDB connection-string scheme.
  const validScheme =
    uri?.startsWith("mongodb://") || uri?.startsWith("mongodb+srv://");

  if (!validScheme) {
    throw new Error("Set a valid MONGODB_URI in server/.env.");
  }

  if (!dbName || !/^[a-zA-Z0-9_-]+$/.test(dbName)) {
    throw new Error(
      "MONGODB_DB_NAME must contain only letters, numbers, underscores, and hyphens.",
    );
  }

  // Return only the settings the database module needs.
  return { uri, dbName };
}

// Environment variables are strings.
// Convert the port to a number and validate it.
export function getPort() {
  const port = Number(process.env.PORT || 3002);

  if (!Number.isInteger(port) || port < 1 || port > 65535) {
    throw new Error("PORT must be an integer between 1 and 65535.");
  }
  return port;
}

// How many reverse proxies sit in front of the API.
// On Render every visitor arrives through Render's proxy. Without this, every
// visitor appears to have the same IP, so one bot's bad logins lock out everyone.
//   TRUST_PROXY_HOPS=1   Render (one proxy)
//   TRUST_PROXY_HOPS=2   Render behind Cloudflare
//   TRUST_PROXY_HOPS=0   no proxy at all
// Never set a number higher than the real number of proxies: visitors could then
// fake their IP address with an X-Forwarded-For header and dodge rate limits.
export function getTrustProxy(env = process.env) {
  const raw = env.TRUST_PROXY_HOPS?.trim();

  if (!raw) {
    if (env.NODE_ENV === "production") {
      throw new Error(
        "Set TRUST_PROXY_HOPS in production (1 on Render, 0 if there is no proxy).",
      );
    }
    return false; // local development: trust no forwarded headers
  }

  const hops = Number(raw);
  if (!Number.isInteger(hops) || hops < 0 || hops > 3) {
    throw new Error("TRUST_PROXY_HOPS must be a whole number from 0 to 3.");
  }
  return hops === 0 ? false : hops;
}

server/public

logs
*.log

Check that .env is ignored

Nothing should print from the second line. If git prints .env, it is not being ignored.

git check-ignore server/.env
git ls-files | grep '\.env$'

If you already committed .env

This stops tracking the file. The old password is still in your Git history, so also change the password on the database.

git rm --cached server/.env
git commit -m "Stop tracking .env"
