What Is Node And Express

Node runs JavaScript outside of the browser. Express is a package that turns Node into a web server. A request comes in, goes down the list of app.use and route lines in order, and the first one that sends a response ends it. Terminal setup is on the Setup page.

Pick Your Setup

Where your data lives decides which files you need. Find your project below, then only follow that one setup. The examples use the word item on purpose. See the rename list below for how to swap in pizza, game, or anything else.

                         Setup 1          Setup 2           Setup 3
                         Data + Database  Data Folder Only  Database Only
data/items.js            Yes              Yes               No
Database                 Yes              No                Yes
.env file                Yes              No                Yes
config/database.js       Yes              No                Yes
Start data comes from    data folder      data folder       Empty table
ids come from            Database         You type them     Database
Saved changes last       Yes              Until restart     Yes
  • Setup 1: Data Folder And A Database. The data folder fills the database once, then the database is the real copy. Use this when you want starter records that users can change.
  • Setup 2: Data Folder Only. The data folder is all you have. Use this for a menu, a list of products, or practice. pizza-menu is this one.
  • Setup 3: Database Only. The table starts empty and users add everything. Use this for accounts, posts, comments, or orders.

Routes And Controllers

A request goes through three files in order: server.js sends it to the routes file, the routes file sends it to a controller function, and the controller sends back the response.

  • Routes only say which URL goes to which function. They look the same in every setup.
  • Controllers do the work: get the data, check it, and send the response. They change with each setup because the data lives in a different place.

  • Full routes file: GET, POST, PATCH, and DELETE
  • Routes for reading only: just the two GET routes

Files Every Setup Uses

These three files are the same in all three setups. server.js and the routes never know where the data comes from. Only the controller knows, and that is why each setup below has its own controller.

server/server.js

This is the Setup 2 version, and it needs no .env. For Setup 1 and Setup 3, add import "dotenv/config"; as the very first line. MongoDB also has to connect before listening, which is on the MongoDB page. The two handlers at the bottom have to stay after every route.

import express from "express";
import itemsRouter from "./routes/items.js";
import { HttpError } from "./utils/HttpError.js";

const PORT = process.env.PORT || 3000;

const app = express();

app.use(express.json());

app.get("/api/health", (req, res) => {
  res.status(200).json({ status: "ok" });
});

app.use("/api/items", itemsRouter);

// No route above matched.
app.use((req, res) => {
  res.status(404).json({ error: "Route not found." });
});

// Express knows this is the error handler because it has four parameters.
app.use((error, req, res, next) => {
  if (error instanceof HttpError) {
    return res.status(error.status).json({ error: error.message });
  }

  console.error(error);
  res.status(500).json({ error: "An unexpected server error occurred." });
});

app.listen(PORT, () => {
  console.log(`🚀 Server listening on http://localhost:${PORT}`);
});

server/utils/HttpError.js

Throw this from a controller to send an error with a status code, such as throw new HttpError(404, "Item not found.").

export class HttpError extends Error {
  constructor(status, message) {
    super(message);
    this.status = status;
  }
}

Paths in this file start after the /api/items in server.js, so "/" means /api/items and "/:id" means /api/items/5.

Setup 1 server/config/reset.js

This deletes the table, makes it again, and copies in your data. Only run it by hand. Never add it to your start script.

import { pool } from "./database.js";
import itemData from "../data/items.js";

const createTableQuery = `
  DROP TABLE IF EXISTS items;

  CREATE TABLE items (
    id SERIAL PRIMARY KEY,
    title VARCHAR(255) NOT NULL,
    description TEXT NOT NULL DEFAULT '',
    image TEXT NOT NULL DEFAULT '',
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
  );
`;

const insertQuery = `
  INSERT INTO items (title, description, image)
  VALUES ($1, $2, $3);
`;

try {
  await pool.query(createTableQuery);

  for (const item of itemData) {
    await pool.query(insertQuery, [item.title, item.description, item.image]);
  }

  console.log(`🎉 Finished! Saved ${itemData.length} items.`);
} catch (error) {
  console.error("⚠️ Reset failed:", error.code || error.message);
  process.exitCode = 1;
} finally {
  await pool.end();
}

Setup 1 server/controllers/items.js

Nothing here imports the data folder. Once the reset has run, the database has the data.

import { pool } from "../config/database.js";
import { HttpError } from "../utils/HttpError.js";

// An id has to be a whole number before it goes to the database.
const readId = (value) => {
  if (!/^\d{1,9}$/.test(value)) throw new HttpError(404, "Item not found.");
  return Number(value);
};

// Only copy the fields you expect. Never save the whole req.body.
const pickFields = (body) => {
  if (typeof body?.title !== "string" || !body.title.trim()) {
    throw new HttpError(400, "Title is required.");
  }

  return [
    body.title.trim(),
    String(body.description ?? ""),
    String(body.image ?? ""),
  ];
};

const getItems = async (req, res) => {
  const results = await pool.query("SELECT * FROM items ORDER BY id ASC");

  res.status(200).json(results.rows);
};

const getItemById = async (req, res) => {
  const results = await pool.query("SELECT * FROM items WHERE id = $1", [
    readId(req.params.id),
  ]);

  if (results.rows.length === 0) throw new HttpError(404, "Item not found.");
  res.status(200).json(results.rows[0]);
};

const createItem = async (req, res) => {
  const results = await pool.query(
    `INSERT INTO items (title, description, image)
    VALUES ($1, $2, $3)
    RETURNING *`,
    pickFields(req.body),
  );

  res.status(201).json(results.rows[0]);
};

const updateItem = async (req, res) => {
  const id = readId(req.params.id);
  const results = await pool.query(
    `UPDATE items SET title = $1, description = $2, image = $3
    WHERE id = $4
    RETURNING *`,
    [...pickFields(req.body), id],
  );

  if (results.rows.length === 0) throw new HttpError(404, "Item not found.");
  res.status(200).json(results.rows[0]);
};

const deleteItem = async (req, res) => {
  const results = await pool.query(
    "DELETE FROM items WHERE id = $1 RETURNING *",
    [readId(req.params.id)],
  );

  if (results.rows.length === 0) throw new HttpError(404, "Item not found.");
  res.status(200).json(results.rows[0]);
};

export default { getItems, getItemById, createItem, updateItem, deleteItem };

Setup 2 server/controllers/items.js with full CRUD

Use this one with the full routes file when you want to practice POST, PATCH, and DELETE without a database.

import itemData from "../data/items.js";
import { HttpError } from "../utils/HttpError.js";

// Work on a copy of the array from the data folder.
let items = [...itemData];
let nextId = Math.max(0, ...items.map((item) => item.id)) + 1;

// Only copy the fields you expect. Never save the whole req.body.
const pickFields = (body) => {
  if (typeof body?.title !== "string" || !body.title.trim()) {
    throw new HttpError(400, "Title is required.");
  }

  return {
    title: body.title.trim(),
    description: String(body.description ?? ""),
    image: String(body.image ?? ""),
  };
};

// req.params.id is always text, so turn it into a number before comparing.
const findItem = (id) => {
  const item = items.find((other) => other.id === Number(id));

  if (!item) throw new HttpError(404, "Item not found.");
  return item;
};

const getItems = (req, res) => {
  res.status(200).json(items);
};

const getItemById = (req, res) => {
  res.status(200).json(findItem(req.params.id));
};

const createItem = (req, res) => {
  const item = { id: nextId, ...pickFields(req.body) };

  nextId += 1;
  items.push(item);
  res.status(201).json(item);
};

const updateItem = (req, res) => {
  const item = findItem(req.params.id);

  Object.assign(item, pickFields(req.body));
  res.status(200).json(item);
};

const deleteItem = (req, res) => {
  const item = findItem(req.params.id);

  items = items.filter((other) => other.id !== item.id);
  res.status(200).json(item);
};

export default { getItems, getItemById, createItem, updateItem, deleteItem };

How server.js Works

Almost every server.js has the same parts in the same order. A request starts at the top and moves down until something sends a response, so moving a part can break the server without showing an error.

The order of a server.js file

  1. Load .env. This goes first so other files can read process.env.
  2. Imports. Express, your routes, and HttpError.
  3. Settings. Values such as PORT.
  4. Create the app. const app = express().
  5. Middleware. This runs on requests before they reach a route, such as express.json().
  6. Routes. Each one matches a URL and sends a response.
  7. 404 handler. Only requests that no route answered get here.
  8. Error handler. This catches anything a route throws. It goes after the routes.
  9. Start listening. app.listen goes last.

The smallest server.js that works

Start here to prove that Express runs. It needs no other files.

import express from "express";

const app = express();

app.get("/api/health", (req, res) => {
  res.status(200).json({ status: "ok" });
});

app.listen(3000, () => {
  console.log("Server listening on http://localhost:3000");
});

What each piece does

import "dotenv/config"     Reads .env into process.env
express()                  Creates the app
app.use(something)         Runs on every request
app.use("/path", router)   Sends requests that start with /path to that router
app.get("/path", fn)       Runs fn for a GET request to exactly that path
express.json()             Turns JSON from fetch into req.body
req                        What came in: params, query, body, headers
res                        What goes back: res.status(200).json(data)
next                       Passes the request to the next function
next(error)                Skips ahead to the error handler
app.listen(PORT, fn)       Opens the port and runs fn once it is ready

Mistakes caused by the wrong order

req.body is undefined        express.json() is missing or below the route
Every URL gives a 404        The 404 handler is above the routes
Errors come back as HTML     The error handler is missing or above the routes
Error handler never runs     It needs all four: (error, req, res, next)
Request hangs forever        A function never sent a response or called next()
Cannot set headers after     A function responded twice, so add return before
they are sent                the first response
CORS error stays             cors() has to be above the routes

A Regular server.js

This is what a normal server.js looks like once the project is real. It has comments for each part and works with the HttpError, routes, and controller files from any setup above. For Setup 2, leave out the dotenv line. If you use the Vite proxy from the React page, leave out the two cors lines and run the server without that package.

server/server.js with every part explained

// 1. Load .env first so everything below can read process.env.
import "dotenv/config";

// 2. Imports. Your own files need ./ and .js on the end.
import express from "express";
import cors from "cors";
import itemsRouter from "./routes/items.js";
import { HttpError } from "./utils/HttpError.js";

// 3. Settings. The host sets PORT when the site is live.
const PORT = process.env.PORT || 3000;
const CLIENT_ORIGIN = process.env.CLIENT_ORIGIN || "http://localhost:5173";

// 4. Create the app.
const app = express();

// 5. Middleware. These run in order before any route.
app.use(cors({ origin: CLIENT_ORIGIN }));
app.use(express.json({ limit: "100kb" }));

app.use((req, res, next) => {
  console.log(`${req.method} ${req.path}`);
  next();
});

// 6. Routes. Paths inside itemsRouter start after /api/items.
app.get("/api/health", (req, res) => {
  res.status(200).json({ status: "ok" });
});

app.use("/api/items", itemsRouter);

// 7. No route above matched.
app.use((req, res) => {
  res.status(404).json({ error: "Route not found." });
});

// 8. Express knows this is the error handler because it has four parameters.
app.use((error, req, res, next) => {
  if (error instanceof HttpError) {
    return res.status(error.status).json({ error: error.message });
  }

  // express.json() could not read the JSON that was sent.
  if (error.type === "entity.parse.failed") {
    return res.status(400).json({ error: "Invalid JSON." });
  }

  // Log the real error, but never send those details to the browser.
  console.error(error);
  res.status(500).json({ error: "An unexpected server error occurred." });
});

// 9. Start the server last.
app.listen(PORT, () => {
  console.log(`🚀 Server listening on http://localhost:${PORT}`);
});

Each resource gets its own routes file and controller file, then one import and one app.use line in server.js. The app.use line goes above the 404 handler.

Reading A Request

The four places data comes from

app.post("/api/items/:id", (req, res) => {
  req.params.id;            // /api/items/5           gives "5"
  req.query.page;           // /api/items?page=2      gives "2"
  req.body.title;           // JSON sent by fetch     needs express.json()
  req.get("Authorization"); // a request header
});

Sending a response

res.status(200).json(data);                      // send JSON
res.status(201).json(newItem);                   // something was created
res.status(204).end();                           // worked, nothing to send back
res.status(400).json({ error: "Bad input." });   // the request was wrong
res.status(404).json({ error: "Not found." });   // no such record
res.status(500).json({ error: "Server error." }); // our code failed

Status codes

200 OK                   It worked
201 Created              POST made a new record
204 No Content           It worked and there is nothing to send back
400 Bad Request          The data sent was invalid
401 Unauthorized         Not signed in
403 Forbidden            Signed in, but not allowed
404 Not Found            No such route or record
409 Conflict             Duplicate, or blocked by related records
413 Content Too Large    The request body is too big
429 Too Many Requests    Rate limit reached
500 Server Error         Something broke in our code
503 Service Unavailable  The database or a service is down

Page number from the query string

Everything in req.query is text or missing, so check it before using it. This came from the Rev games controller.

const limit = 24;
const raw = req.query.page ?? "1";

if (typeof raw !== "string" || !/^\d{1,4}$/.test(raw)) {
  throw new HttpError(400, "Page must be a whole number between 1 and 1000.");
}

const page = Number(raw);
const skip = (page - 1) * limit;

Middleware

Middleware is a function that runs between the request coming in and the response going out. It either sends a response or calls next() to pass the request along. Order matters, because Express runs them from top to bottom.

Log every request

app.use((req, res, next) => {
  console.log(`${req.method} ${req.path}`);
  next();
});

Protect one route

Put the middleware between the path and the controller. The Security page has the real version.

const requireKey = (req, res, next) => {
  if (req.get("X-Api-Key") !== process.env.API_KEY) {
    return res.status(401).json({ error: "Missing or wrong key." });
  }
  next();
};

router.post("/", requireKey, ItemsController.createItem);

Errors In Express 4 And 5

New projects install Express 5. xenoblade1_Locations and video_gameStore use Express 4, and unearthed and Rev use Express 5. Check the version in package.json before you reuse old code.

Express 5: a thrown error reaches the error handler

const getItem = async (req, res) => {
  const item = await Item.findById(req.params.id);

  if (!item) throw new HttpError(404, "Item not found.");
  res.status(200).json(item);
};

Express 4: async functions need try and catch

const getItem = async (req, res, next) => {
  try {
    const item = await Item.findById(req.params.id);

    if (!item) throw new HttpError(404, "Item not found.");
    res.status(200).json(item);
  } catch (error) {
    next(error);
  }
};

Serve React From Express

This is for going live, when Express serves the finished React site. Run npm run build first, which puts the site in server/public because of the outDir in vite.config.js. The old app.get("/*") line from my class projects crashes on Express 5, so this version uses app.use instead.

Add to server.js after the API routes

import path from "path";

if (process.env.NODE_ENV === "production") {
  app.use(express.static("public"));

  // Unknown /api paths still get a JSON 404 from the handler below this block.
  app.use((req, res, next) => {
    if (req.path.startsWith("/api")) return next();
    res.sendFile(path.resolve("public", "index.html"));
  });
}

Split App And Server For Testing

This is how Rev is built. app.js builds the app and server.js starts it, so a test can use the app without opening a real port or a database.

server/app.js

import express from "express";

export function createApp() {
  const app = express();

  app.use(express.json());

  app.get("/api/health", (req, res) => {
    res.status(200).json({ status: "ok" });
  });

  app.use((req, res) => {
    res.status(404).json({ error: "Route not found." });
  });

  return app;
}

server/test/health.test.js

import test from "node:test";
import assert from "node:assert/strict";
import { createApp } from "../app.js";

test("GET /api/health answers ok", async () => {
  const server = createApp().listen(0);
  const { port } = server.address();

  try {
    const response = await fetch(`http://127.0.0.1:${port}/api/health`);

    assert.equal(response.status, 200);
    assert.deepEqual(await response.json(), { status: "ok" });
  } finally {
    server.close();
  }
});
