What Is Node And Express

Node runs JavaScript outside of the browser. Express is a package that turns Node into a web server. A request comes in, goes down the list of app.use and route lines in order, and the first one that sends a response ends it. Terminal setup is on the Setup page.

There are two kinds of code boxes on this page:

  • A box named after a file, such as server/server.js, belongs to one of the three setups. It runs once the other files from that setup are in place.
  • Every other Node box runs on its own. Its first comment says "Runs on its own".

A practice folder for the boxes that run on their own

Make this folder once. After that, save any box that runs on its own as server.js inside it and run node server.js.

mkdir try-it
cd try-it
npm init -y
npm pkg set type=module
npm install express cors

Routes And Controllers

A request goes through three files in order: server.js sends it to the routes file, the routes file sends it to a controller function, and the controller sends back the response.

  • Routes only say which URL goes to which function. They look the same in every setup.
  • Controllers do the work: get the data, check it, and send the response. They change with each setup because the data lives in a different place.

Files Every Setup Uses

These three files are the same in all three setups. server.js and the routes never know where the data comes from. Only the controller knows, and that is why each setup below has its own controller.

server/server.js

This is the Setup 2 version, and it needs no .env.

  • Setup 1 and Setup 3: add import "dotenv/config"; as the very first line.
  • MongoDB: it also has to connect before listening, which is on the MongoDB page.
  • Order: the two handlers at the bottom have to stay after every route.
// Express is the web server package. Install it with: npm install express
import express from "express";
// Your own files need ./ at the start and .js on the end.
import itemsRouter from "./routes/items.js";
import { HttpError } from "./utils/HttpError.js";

// The host sets PORT when the site is live. 3000 is for your own computer.
const PORT = process.env.PORT || 3000;

// Create the app. Everything below is added to it in order.
const app = express();

// Turns JSON from fetch into req.body. A body over 100kb is refused.
app.use(express.json({ limit: "100kb" }));

// A quick route to prove the server is running.
app.get("/api/health", (req, res) => {
  res.status(200).json({ status: "ok" });
});

// Every URL that starts with /api/items goes to the routes file.
app.use("/api/items", itemsRouter);

// No route above matched.
app.use((req, res) => {
  res.status(404).json({ error: "Route not found." });
});

// Express knows this is the error handler because it has four parameters.
app.use((error, req, res, next) => {
  // An error a controller threw on purpose, such as a 404.
  if (error instanceof HttpError) {
    return res.status(error.status).json({ error: error.message });
  }

  // express.json() could not read the request body.
  if (error.type === "entity.parse.failed") {
    return res.status(400).json({ error: "Invalid JSON." });
  }
  // The body was bigger than the 100kb limit.
  if (error.type === "entity.too.large") {
    return res.status(413).json({ error: "Request body is too large." });
  }

  // Anything else is a bug. Log the real error, but never send it to the browser.
  console.error(error);
  res.status(500).json({ error: "An unexpected server error occurred." });
});

// Start the server last, after every route and handler is added.
app.listen(PORT, (error) => {
  if (error) throw error; // e.g. the port is already in use
  console.log(`🚀 Server listening on http://localhost:${PORT}`);
});

Pro-Tip: The controllers on this page throw errors inside async functions. Only Express 5 sends those to the error handler. On Express 4 the error never gets there and the server crashes. Run npm ls express to check, and see Errors In Express 4 And 5.

server/utils/HttpError.js

Throw this from a controller to send an error with a status code, such as throw new HttpError(404, "Item not found.").

// A normal Error only has a message. This one also carries a status code,
// so the error handler in server.js knows which status to send back.
export class HttpError extends Error {
  constructor(status, message) {
    // super() runs the normal Error setup and saves the message.
    super(message);
    // Save the status code, such as 400 or 404.
    this.status = status;
  }
}

server/routes/items.js

Paths in this file start after the /api/items in server.js, so "/" means /api/items and "/:id" means /api/items/5.

import express from "express";
// The controller has the functions that do the real work.
import ItemsController from "../controllers/items.js";

// A router is a small app that only holds routes.
const router = express.Router();

// GET /api/items sends back every item.
router.get("/", ItemsController.getItems);
// GET /api/items/5 sends back one item.
router.get("/:id", ItemsController.getItemById);
// POST /api/items makes a new item.
router.post("/", ItemsController.createItem);
// PATCH /api/items/5 changes part of an item.
router.patch("/:id", ItemsController.updateItem);
// DELETE /api/items/5 removes an item.
router.delete("/:id", ItemsController.deleteItem);

// server.js imports this as itemsRouter.

Setup 1 server/config/database.js

A hosted database uses SSL here. rejectUnauthorized: false still encrypts the connection, but it skips checking the host's certificate, so this is fine for practice. For a real product, use your host's CA certificate.

// Reads .env into process.env. It is here as well as in server.js,
// because reset.js and createTable.js run this file without server.js.
import "dotenv/config";
import pg from "pg";

// A database on your own computer does not use SSL. A hosted one does.
const isLocal = ["localhost", "127.0.0.1"].includes(process.env.PGHOST);

// A pool keeps a few connections open and reuses them for every query.
export const pool = new pg.Pool({
  user: process.env.PGUSER,
  password: process.env.PGPASSWORD,
  host: process.env.PGHOST,
  port: process.env.PGPORT,
  database: process.env.PGDATABASE,
  // Encrypt the connection when the database is hosted.
  ssl: isLocal ? false : { rejectUnauthorized: false },
});

Pro-Tip: If you see ECONNREFUSED 127.0.0.1:5432 while using a hosted database, .env did not load. When PGHOST is empty, pg tries a database on your own computer instead.

Setup 1 server/config/reset.js

This deletes the table, makes it again, and copies in your data. Only run it by hand. Never add it to your start script.

import { pool } from "./database.js";
import itemData from "../data/items.js";

// Delete the old table, then make a new empty one.
// SERIAL makes the id count up by itself. TIMESTAMPTZ saves the date and time.
const createTableQuery = `
  DROP TABLE IF EXISTS items;

  CREATE TABLE items (
    id SERIAL PRIMARY KEY,
    title VARCHAR(255) NOT NULL,
    description TEXT NOT NULL DEFAULT '',
    image TEXT NOT NULL DEFAULT '',
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
  );
`;

// $1, $2, and $3 are placeholders. The database fills them in safely.
const insertQuery = `
  INSERT INTO items (title, description, image)
  VALUES ($1, $2, $3);
`;

try {
  await pool.query(createTableQuery);

  // Save one row for each record in the data folder.
  // The array order has to match $1, $2, $3 above.
  for (const item of itemData) {
    await pool.query(insertQuery, [item.title, item.description, item.image]);
  }

  console.log(`🎉 Finished! Saved ${itemData.length} items.`);
} catch (error) {
  // Show what went wrong, and tell the terminal that the script failed.
  console.error("⚠️ Reset failed:", error.code || error.message);
  process.exitCode = 1;
} finally {
  // Always close the pool, or the script never gives the prompt back.
  await pool.end();
}

Pro-Tip: This deletes the items table in whichever database .env points at. Check PGHOST and PGDATABASE before you run it, so you never reset a live site by mistake.

Setup 1 server/controllers/items.js

Nothing here imports the data folder. Once the reset has run, the database has the data.

import { pool } from "../config/database.js";
import { HttpError } from "../utils/HttpError.js";

// An id has to be a whole number before it goes to the database.
// 1 to 9 digits also keeps it small enough for the id column.
const readId = (value) => {
  if (!/^\d{1,9}$/.test(value)) throw new HttpError(404, "Item not found.");
  return Number(value);
};

// Only copy the fields you expect. Never save the whole req.body.
const pickFields = (body) => {
  // The title has to be text with at least one real character in it.
  if (typeof body?.title !== "string" || !body.title.trim()) {
    throw new HttpError(400, "Title is required.");
  }

  // The title column is VARCHAR(255), so longer text would fail in the database.
  if (body.title.trim().length > 255) {
    throw new HttpError(400, "Title must be 255 characters or fewer.");
  }

  // This order has to match $1, $2, $3 in the queries below.
  // ?? "" saves a field that was left out as empty text.
  return [
    body.title.trim(),
    String(body.description ?? ""),
    String(body.image ?? ""),
  ];
};

// GET /api/items
const getItems = async (req, res) => {
  const results = await pool.query("SELECT * FROM items ORDER BY id ASC");

  // results.rows is an array with one object for each row.
  res.status(200).json(results.rows);
};

// GET /api/items/:id
const getItemById = async (req, res) => {
  // $1 is filled in from the array, so the id never becomes part of the SQL text.
  const results = await pool.query("SELECT * FROM items WHERE id = $1", [
    readId(req.params.id),
  ]);

  // No row came back, so that id does not exist.
  if (results.rows.length === 0) throw new HttpError(404, "Item not found.");
  res.status(200).json(results.rows[0]);
};

// POST /api/items
const createItem = async (req, res) => {
  // RETURNING * sends back the new row, with the id the database made.
  const results = await pool.query(
    `INSERT INTO items (title, description, image)
    VALUES ($1, $2, $3)
    RETURNING *`,
    pickFields(req.body),
  );

  // 201 means something was created.
  res.status(201).json(results.rows[0]);
};

// PATCH /api/items/:id
const updateItem = async (req, res) => {
  const id = readId(req.params.id);
  // Get the saved row first, so fields the request left out can be kept.
  const found = await pool.query("SELECT * FROM items WHERE id = $1", [id]);

  if (found.rows.length === 0) throw new HttpError(404, "Item not found.");

  // PATCH keeps any field the request left out.
  // The saved row goes first and req.body second, so the new values win.
  const results = await pool.query(
    `UPDATE items SET title = $1, description = $2, image = $3
    WHERE id = $4
    RETURNING *`,
    [...pickFields({ ...found.rows[0], ...req.body }), id],
  );

  // The row could have been deleted between the two queries.
  if (results.rows.length === 0) throw new HttpError(404, "Item not found.");
  res.status(200).json(results.rows[0]);
};

// DELETE /api/items/:id
const deleteItem = async (req, res) => {
  // RETURNING * sends back the row that was deleted.
  const results = await pool.query(
    "DELETE FROM items WHERE id = $1 RETURNING *",
    [readId(req.params.id)],
  );

  if (results.rows.length === 0) throw new HttpError(404, "Item not found.");
  res.status(200).json(results.rows[0]);
};

// The routes file uses these names, such as ItemsController.getItems.
export default { getItems, getItemById, createItem, updateItem, deleteItem };

Pro-Tip: Keep every value in the array, as $1, $2, and $3. Never put req.params or req.body into the SQL text with ${ }, because that lets a visitor run their own SQL. This is called SQL injection.

Setup 2 server/controllers/items.js with full CRUD

Use this one with the full routes file when you want to practice POST, PATCH, and DELETE without a database.

import itemData from "../data/items.js";
import { HttpError } from "../utils/HttpError.js";

// Work on a copy of the array from the data folder.
let items = [...itemData];
// The next id is one more than the biggest id in the data. The 0 covers an empty array.
let nextId = Math.max(0, ...items.map((item) => item.id)) + 1;

// Only copy the fields you expect. Never save the whole req.body.
const pickFields = (body) => {
  // The title has to be text with at least one real character in it.
  if (typeof body?.title !== "string" || !body.title.trim()) {
    throw new HttpError(400, "Title is required.");
  }

  if (body.title.trim().length > 255) {
    throw new HttpError(400, "Title must be 255 characters or fewer.");
  }

  // ?? "" saves a field that was left out as empty text.
  return {
    title: body.title.trim(),
    description: String(body.description ?? ""),
    image: String(body.image ?? ""),
  };
};

// req.params.id is always text, so turn it into a number before comparing.
const findItem = (id) => {
  const item = items.find((other) => other.id === Number(id));

  // find gives back undefined when nothing matched.
  if (!item) throw new HttpError(404, "Item not found.");
  return item;
};

// GET /api/items
const getItems = (req, res) => {
  res.status(200).json(items);
};

// GET /api/items/:id
const getItemById = (req, res) => {
  res.status(200).json(findItem(req.params.id));
};

// POST /api/items
const createItem = (req, res) => {
  // The server picks the id. An id sent in the request is ignored.
  const item = { id: nextId, ...pickFields(req.body) };

  nextId += 1;
  items.push(item);
  // 201 means something was created.
  res.status(201).json(item);
};

// PATCH /api/items/:id
const updateItem = (req, res) => {
  const item = findItem(req.params.id);

  // PATCH keeps any field the request left out.
  // The saved item goes first and req.body second, so the new values win.
  Object.assign(item, pickFields({ ...item, ...req.body }));
  res.status(200).json(item);
};

// DELETE /api/items/:id
const deleteItem = (req, res) => {
  const item = findItem(req.params.id);

  // Keep every item except the one being deleted.
  items = items.filter((other) => other.id !== item.id);
  res.status(200).json(item);
};

// The routes file uses these names, such as ItemsController.getItems.
export default { getItems, getItemById, createItem, updateItem, deleteItem };

// Reads .env into process.env. It is here as well as in server.js,
// because reset.js and createTable.js run this file without server.js.
import "dotenv/config";
import pg from "pg";

// A database on your own computer does not use SSL. A hosted one does.
const isLocal = ["localhost", "127.0.0.1"].includes(process.env.PGHOST);

// A pool keeps a few connections open and reuses them for every query.
export const pool = new pg.Pool({
  user: process.env.PGUSER,
  password: process.env.PGPASSWORD,
  host: process.env.PGHOST,
  port: process.env.PGPORT,
  database: process.env.PGDATABASE,
  // Encrypt the connection when the database is hosted.
  ssl: isLocal ? false : { rejectUnauthorized: false },
});

Setup 3 server/controllers/items.js

This is the same controller as Setup 1, because both only talk to the database.

import { pool } from "../config/database.js";
import { HttpError } from "../utils/HttpError.js";

// An id has to be a whole number before it goes to the database.
// 1 to 9 digits also keeps it small enough for the id column.
const readId = (value) => {
  if (!/^\d{1,9}$/.test(value)) throw new HttpError(404, "Item not found.");
  return Number(value);
};

// Only copy the fields you expect. Never save the whole req.body.
const pickFields = (body) => {
  // The title has to be text with at least one real character in it.
  if (typeof body?.title !== "string" || !body.title.trim()) {
    throw new HttpError(400, "Title is required.");
  }

  // The title column is VARCHAR(255), so longer text would fail in the database.
  if (body.title.trim().length > 255) {
    throw new HttpError(400, "Title must be 255 characters or fewer.");
  }

  // This order has to match $1, $2, $3 in the queries below.
  // ?? "" saves a field that was left out as empty text.
  return [
    body.title.trim(),
    String(body.description ?? ""),
    String(body.image ?? ""),
  ];
};

// GET /api/items
const getItems = async (req, res) => {
  const results = await pool.query("SELECT * FROM items ORDER BY id ASC");

  // results.rows is an array with one object for each row.
  res.status(200).json(results.rows);
};

// GET /api/items/:id
const getItemById = async (req, res) => {
  // $1 is filled in from the array, so the id never becomes part of the SQL text.
  const results = await pool.query("SELECT * FROM items WHERE id = $1", [
    readId(req.params.id),
  ]);

  // No row came back, so that id does not exist.
  if (results.rows.length === 0) throw new HttpError(404, "Item not found.");
  res.status(200).json(results.rows[0]);
};

// POST /api/items
const createItem = async (req, res) => {
  // RETURNING * sends back the new row, with the id the database made.
  const results = await pool.query(
    `INSERT INTO items (title, description, image)
    VALUES ($1, $2, $3)
    RETURNING *`,
    pickFields(req.body),
  );

  // 201 means something was created.
  res.status(201).json(results.rows[0]);
};

// PATCH /api/items/:id
const updateItem = async (req, res) => {
  const id = readId(req.params.id);
  // Get the saved row first, so fields the request left out can be kept.
  const found = await pool.query("SELECT * FROM items WHERE id = $1", [id]);

  if (found.rows.length === 0) throw new HttpError(404, "Item not found.");

  // PATCH keeps any field the request left out.
  // The saved row goes first and req.body second, so the new values win.
  const results = await pool.query(
    `UPDATE items SET title = $1, description = $2, image = $3
    WHERE id = $4
    RETURNING *`,
    [...pickFields({ ...found.rows[0], ...req.body }), id],
  );

  // The row could have been deleted between the two queries.
  if (results.rows.length === 0) throw new HttpError(404, "Item not found.");
  res.status(200).json(results.rows[0]);
};

// DELETE /api/items/:id
const deleteItem = async (req, res) => {
  // RETURNING * sends back the row that was deleted.
  const results = await pool.query(
    "DELETE FROM items WHERE id = $1 RETURNING *",
    [readId(req.params.id)],
  );

  if (results.rows.length === 0) throw new HttpError(404, "Item not found.");
  res.status(200).json(results.rows[0]);
};

// The routes file uses these names, such as ItemsController.getItems.
export default { getItems, getItemById, createItem, updateItem, deleteItem };

Pro-Tip: Keep every value in the array, as $1, $2, and $3. Never put req.params or req.body into the SQL text with ${ }, because that lets a visitor run their own SQL. This is called SQL injection.

How server.js Works

Almost every server.js has the same parts in the same order. A request starts at the top and moves down until something sends a response, so moving a part can break the server without showing an error.

The order of a server.js file

  1. Load .env. This goes first so other files can read process.env.
  2. Imports. Express, your routes, and HttpError.
  3. Settings. Values such as PORT.
  4. Create the app. const app = express().
  5. Middleware. This runs on requests before they reach a route, such as express.json().
  6. Routes. Each one matches a URL and sends a response.
  7. 404 handler. Only requests that no route answered get here.
  8. Error handler. This catches anything a route throws. It goes after the routes.
  9. Start listening. app.listen goes last.

The smallest server.js that works

Start here to prove that Express runs. It needs no other files.

// Runs on its own. Save it as server.js, then run: node server.js
import express from "express";

// Create the app.
const app = express();

// One route. A GET request to /api/health gets this JSON back.
app.get("/api/health", (req, res) => {
  res.status(200).json({ status: "ok" });
});

// Open port 3000 and wait for requests.
app.listen(3000, (error) => {
  if (error) throw error; // e.g. the port is already in use
  console.log("Server listening on http://localhost:3000");
});

What each piece does

import "dotenv/config"     Reads .env into process.env
express()                  Creates the app
app.use(something)         Runs on every request
app.use("/path", router)   Sends requests that start with /path to that router
app.get("/path", fn)       Runs fn for a GET request to exactly that path
express.json()             Turns JSON from fetch into req.body
req                        What came in: params, query, body, headers
res                        What goes back: res.status(200).json(data)
next                       Passes the request to the next function
next(error)                Skips ahead to the error handler
app.listen(PORT, fn)       Opens the port, then runs fn(error). Check error: Express 5 hands it to fn instead of crashing

Mistakes caused by the wrong order

req.body is undefined        express.json() is missing or below the route
Every URL gives a 404        The 404 handler is above the routes
Errors come back as HTML     The error handler is missing or above the routes
Error handler never runs     It needs all four: (error, req, res, next)
Request hangs forever        A function never sent a response or called next()
Cannot set headers after     A function responded twice, so add return before
they are sent                the first response
CORS error stays             cors() has to be above the routes

server/server.js with every part explained

// 1. Load .env first so everything below can read process.env.
import "dotenv/config";

// 2. Imports. Your own files need ./ and .js on the end.
import express from "express";
import cors from "cors";
import itemsRouter from "./routes/items.js";
import { HttpError } from "./utils/HttpError.js";

// 3. Settings. The host sets PORT when the site is live.
const PORT = process.env.PORT || 3000;
const CLIENT_ORIGIN = process.env.CLIENT_ORIGIN || "http://localhost:5173";

// 4. Create the app.
const app = express();

// 5. Middleware. These run in order before any route.
app.use(cors({ origin: CLIENT_ORIGIN }));
app.use(express.json({ limit: "100kb" }));

app.use((req, res, next) => {
  console.log(`${req.method} ${req.path}`);
  next();
});

// 6. Routes. Paths inside itemsRouter start after /api/items.
app.get("/api/health", (req, res) => {
  res.status(200).json({ status: "ok" });
});

app.use("/api/items", itemsRouter);

// 7. No route above matched.
app.use((req, res) => {
  res.status(404).json({ error: "Route not found." });
});

// 8. Express knows this is the error handler because it has four parameters.
app.use((error, req, res, next) => {
  if (error instanceof HttpError) {
    return res.status(error.status).json({ error: error.message });
  }

  // express.json() could not read the request body.
  if (error.type === "entity.parse.failed") {
    return res.status(400).json({ error: "Invalid JSON." });
  }
  if (error.type === "entity.too.large") {
    return res.status(413).json({ error: "Request body is too large." });
  }

  // Log the real error, but never send those details to the browser.
  console.error(error);
  res.status(500).json({ error: "An unexpected server error occurred." });
});

// 9. Start the server last.
app.listen(PORT, (error) => {
  if (error) throw error; // e.g. the port is already in use
  console.log(`🚀 Server listening on http://localhost:${PORT}`);
});

Start the server after the database connects

With a database, replace step 9 with this so the server only opens once the connection works. The connectDatabase code is on the MongoDB page. This box uses a pretend connectDatabase so that it runs on its own.

// Runs on its own. Save it as server.js, then run: node server.js
import express from "express";

const PORT = process.env.PORT || 3000;

const app = express();

// This stands in for the real connectDatabase in config/database.js.
// MongoDB:  await mongoose.connect(process.env.MONGODB_URI);
// Postgres: await pool.query("SELECT 1");
async function connectDatabase() {
  // Pretend the database takes half a second to answer.
  await new Promise((resolve) => setTimeout(resolve, 500));
  console.log("Database connected.");
}

app.get("/api/health", (req, res) => {
  res.status(200).json({ status: "ok" });
});

try {
  // Wait here until the database answers. Nothing below runs before that.
  await connectDatabase();

  // The port only opens once the database is ready.
  app.listen(PORT, (error) => {
    if (error) throw error; // e.g. the port is already in use
    console.log(`🚀 Server listening on http://localhost:${PORT}`);
  });
} catch (error) {
  // The database did not connect, so the port never opens.
  console.error("Could not connect to the database:", error.message);
  process.exitCode = 1;
}

Pro-Tip: Keep the try and catch. Without it, a wrong password or a database that is down stops the server with a long error instead of one clear line.

Reading A Request

The four places data comes from

// Runs on its own. Save it as server.js, then run: node server.js
import express from "express";

const app = express();

// Without this line req.body is undefined.
app.use(express.json({ limit: "100kb" }));

app.post("/api/items/:id", (req, res) => {
  // 1. params: the :id part of the path.   /api/items/5         gives "5"
  const id = req.params.id;
  // 2. query: what comes after the ?.      /api/items/5?page=2  gives "2"
  const page = req.query.page;
  // 3. body: JSON sent by fetch. The ?. stops a crash when no body was sent.
  const title = req.body?.title;
  // 4. headers: extra information sent along with the request.
  const authorization = req.get("Authorization");

  // Send all four back so you can see what arrived.
  res.status(200).json({ id, page, title, authorization });
});

app.listen(3000, (error) => {
  if (error) throw error; // e.g. the port is already in use
  console.log("Server listening on http://localhost:3000");
});

// Try it from a second terminal. This is one long line:
// curl -X POST "http://localhost:3000/api/items/5?page=2" -H "Content-Type: application/json" -H "Authorization: Bearer abc" -d '{"title":"Hi"}'

Pro-Tip: params, query, and headers are always text or missing, and the body can be anything a visitor sends. Check the type before you use any of them. On Express 5, req.body is undefined when no JSON was sent, which is why the box reads req.body?.title.

Sending a response

// Runs on its own. Save it as server.js, then run: node server.js
import express from "express";

const app = express();

app.use(express.json({ limit: "100kb" }));

const items = [{ id: 1, title: "First Item" }];

app.get("/api/items", (req, res) => {
  res.status(200).json(items); // send JSON
});

app.get("/api/items/:id", (req, res) => {
  const item = items.find((other) => other.id === Number(req.params.id));

  // return stops the function here, so only one response is sent.
  if (!item) {
    return res.status(404).json({ error: "Not found." }); // no such record
  }

  res.status(200).json(item);
});

app.post("/api/items", (req, res) => {
  if (typeof req.body?.title !== "string") {
    return res.status(400).json({ error: "Bad input." }); // the request was wrong
  }

  const newItem = { id: items.length + 1, title: req.body.title };

  items.push(newItem);
  res.status(201).json(newItem); // something was created
});

app.delete("/api/items/:id", (req, res) => {
  res.status(204).end(); // worked, nothing to send back
});

app.get("/api/broken", (req, res) => {
  res.status(500).json({ error: "Server error." }); // our code failed
});

app.listen(3000, (error) => {
  if (error) throw error; // e.g. the port is already in use
  console.log("Server listening on http://localhost:3000");
});

// Try it from a second terminal. -i shows the status code too:
// curl -i http://localhost:3000/api/items/99
// curl -i -X DELETE http://localhost:3000/api/items/1

Pro-Tip: Send one response for each request. Put return in front of an early response, or the function keeps going and you get "Cannot set headers after they are sent".

Status codes

200 OK                   It worked
201 Created              POST made a new record
204 No Content           It worked and there is nothing to send back
400 Bad Request          The data sent was invalid
401 Unauthorized         Not signed in
403 Forbidden            Signed in, but not allowed
404 Not Found            No such route or record
409 Conflict             Duplicate, or blocked by related records
413 Content Too Large    The request body is too big
429 Too Many Requests    Rate limit reached
500 Server Error         Something broke in our code
503 Service Unavailable  The database or a service is down

Page number from the query string

Everything in req.query is text or missing, so check it before using it. This came from the Rev games controller. The range check after Number is there because the pattern alone still lets 0 and 9999 through.

// Runs on its own. Save it as server.js, then run: node server.js
import express from "express";

const app = express();

// In a project, import this from utils/HttpError.js instead.
class HttpError extends Error {
  constructor(status, message) {
    super(message);
    this.status = status;
  }
}

// 100 made up items, so there is something to page through.
const items = Array.from({ length: 100 }, (unused, index) => ({
  id: index + 1,
  title: `Item ${index + 1}`,
}));

app.get("/api/items", (req, res) => {
  // How many items go on one page.
  const limit = 24;
  // No ?page= in the URL means page 1.
  const raw = req.query.page ?? "1";

  // ?page=1&page=2 arrives as an array, and ?page=abc is not a number.
  if (typeof raw !== "string" || !/^\d{1,4}$/.test(raw)) {
    throw new HttpError(400, "Page must be a whole number between 1 and 1000.");
  }

  const page = Number(raw);

  // The pattern above still lets 0 and 9999 through, so check the range too.
  if (page < 1 || page > 1000) {
    throw new HttpError(400, "Page must be a whole number between 1 and 1000.");
  }

  // Page 1 skips 0 items, page 2 skips 24, page 3 skips 48.
  const skip = (page - 1) * limit;

  res.status(200).json({ page, items: items.slice(skip, skip + limit) });
});

// Turns a thrown HttpError into a JSON answer.
app.use((error, req, res, next) => {
  if (error instanceof HttpError) {
    return res.status(error.status).json({ error: error.message });
  }

  console.error(error);
  res.status(500).json({ error: "An unexpected server error occurred." });
});

app.listen(3000, (error) => {
  if (error) throw error; // e.g. the port is already in use
  console.log("Server listening on http://localhost:3000");
});

// Try it from a second terminal:
// curl "http://localhost:3000/api/items?page=2"
// curl "http://localhost:3000/api/items?page=0"

Pro-Tip: With a database, use the same two numbers in the query: LIMIT $1 OFFSET $2 in Postgres, or .skip(skip).limit(limit) in Mongoose. Always sort the query too, or the same record can show up on two pages.

Middleware

Middleware is a function that runs between the request coming in and the response going out. It either sends a response or calls next() to pass the request along. Order matters, because Express runs them from top to bottom.

Log every request

// Runs on its own. Save it as server.js, then run: node server.js
import express from "express";

const app = express();

// There is no path, so this runs on every request. It goes above the routes.
app.use((req, res, next) => {
  // Prints a line such as: GET /api/health
  console.log(`${req.method} ${req.path}`);
  // Pass the request along. Without next() the request hangs forever.
  next();
});

app.get("/api/health", (req, res) => {
  res.status(200).json({ status: "ok" });
});

app.listen(3000, (error) => {
  if (error) throw error; // e.g. the port is already in use
  console.log("Server listening on http://localhost:3000");
});

Pro-Tip: Log the method and the path only. Never log req.body or the headers, because passwords and login tokens would end up in your logs.

Protect one route

Put the middleware between the path and the controller. The Security page has the real version.

// Runs on its own. Save it as server.js, then run: API_KEY=my-secret-key node server.js
import express from "express";

// Stop right away when the key is missing. Without this check, a request
// with no key would match the missing API_KEY and get in.
if (!process.env.API_KEY) {
  throw new Error("API_KEY is not set. Add it to .env first.");
}

const app = express();
const router = express.Router();

app.use(express.json({ limit: "100kb" }));

// Middleware gets req, res, and next, the same as any route function.
const requireKey = (req, res, next) => {
  // req.get reads a request header.
  if (req.get("X-Api-Key") !== process.env.API_KEY) {
    // return stops here, so the controller never runs.
    return res.status(401).json({ error: "Missing or wrong key." });
  }
  // The key matched, so move on to the controller.
  next();
};

// This stands in for ItemsController.createItem.
const createItem = (req, res) => {
  res.status(201).json({ id: 1, title: String(req.body?.title ?? "") });
};

// Anyone can read.
router.get("/", (req, res) => {
  res.status(200).json([]);
});

// The middleware goes between the path and the controller. Only POST needs the key.
router.post("/", requireKey, createItem);

app.use("/api/items", router);

app.listen(3000, (error) => {
  if (error) throw error; // e.g. the port is already in use
  console.log("Server listening on http://localhost:3000");
});

// Try it from a second terminal. The first one gets a 401 and the second a 201:
// curl -i -X POST http://localhost:3000/api/items -H "Content-Type: application/json" -d '{"title":"Hi"}'
// curl -i -X POST http://localhost:3000/api/items -H "Content-Type: application/json" -H "X-Api-Key: my-secret-key" -d '{"title":"Hi"}'

Pro-Tip: When API_KEY is missing from .env, a request with no key matches it and gets in. That is why the box stops at the top if the key is not set. One shared key is fine for practice. For real secrets, compare with timingSafeEqual from node:crypto, the way the Security page does.

Allow a frontend on another address with CORS

You only need this when React and Express are on different addresses and you are not using the Vite proxy. Name your frontend instead of leaving it open to every site.

// Runs on its own. Install both first: npm install express cors
import express from "express";
import cors from "cors";

// The address of your React site. Vite uses 5173 on your own computer.
// Keep the fallback: when origin is missing, no site is allowed at all.
const CLIENT_ORIGIN = process.env.CLIENT_ORIGIN || "http://localhost:5173";

const app = express();

// cors() goes above the routes. Only CLIENT_ORIGIN may read the answers.
app.use(cors({ origin: CLIENT_ORIGIN }));

app.get("/api/health", (req, res) => {
  res.status(200).json({ status: "ok" });
});

app.listen(3000, (error) => {
  if (error) throw error; // e.g. the port is already in use
  console.log("Server listening on http://localhost:3000");
});

// Try it from a second terminal:
// curl -i http://localhost:3000/api/health
// The answer has this line: Access-Control-Allow-Origin: http://localhost:5173

Pro-Tip: CORS only stops browsers. curl and other servers can still call your API, so it does not replace a login. The origin has to match exactly: http or https, the port, and no / on the end. cors() with nothing inside the brackets lets every site in.

Limit the body size

// Runs on its own. Save it as server.js, then run: node server.js
import express from "express";

const app = express();

// A body over 100kb is refused before your route runs.
app.use(express.json({ limit: "100kb" }));

app.post("/api/items", (req, res) => {
  res.status(201).json({ received: req.body });
});

// express.json() sends its errors here. Four parameters make it the error handler.
app.use((error, req, res, next) => {
  // The body was bigger than the limit.
  if (error.type === "entity.too.large") {
    return res.status(413).json({ error: "Request body is too large." });
  }
  // The body was not valid JSON.
  if (error.type === "entity.parse.failed") {
    return res.status(400).json({ error: "Invalid JSON." });
  }

  console.error(error);
  res.status(500).json({ error: "An unexpected server error occurred." });
});

app.listen(3000, (error) => {
  if (error) throw error; // e.g. the port is already in use
  console.log("Server listening on http://localhost:3000");
});

// Try it from a second terminal. The missing } gives a 400:
// curl -i -X POST http://localhost:3000/api/items -H "Content-Type: application/json" -d '{"title":"Hi"'

Pro-Tip: Keep the error handler with it. Without one, Express answers a body that is too large with an HTML error page instead of JSON.

Errors In Express 4 And 5

New projects install Express 5. xenoblade1_Locations and video_gameStore use Express 4, and unearthed and Rev use Express 5. Check the version in package.json before you reuse old code.

Express 5: a thrown error reaches the error handler

// Runs on its own with Express 5. Check your version with: npm ls express
import express from "express";

const app = express();

// In a project, import this from utils/HttpError.js instead.
class HttpError extends Error {
  constructor(status, message) {
    super(message);
    this.status = status;
  }
}

const items = [{ id: 1, title: "First Item" }];

// This stands in for a database call such as Item.findById(id).
const findById = async (id) => items.find((item) => item.id === Number(id));

const getItem = async (req, res) => {
  const item = await findById(req.params.id);

  // Express 5 catches this throw and sends it to the error handler below.
  if (!item) throw new HttpError(404, "Item not found.");
  res.status(200).json(item);
};

app.get("/api/items/:id", getItem);

app.use((error, req, res, next) => {
  if (error instanceof HttpError) {
    return res.status(error.status).json({ error: error.message });
  }

  console.error(error);
  res.status(500).json({ error: "An unexpected server error occurred." });
});

app.listen(3000, (error) => {
  if (error) throw error; // e.g. the port is already in use
  console.log("Server listening on http://localhost:3000");
});

// Try it from a second terminal:
// curl -i http://localhost:3000/api/items/1
// curl -i http://localhost:3000/api/items/99

Express 4: async functions need try and catch

// Runs on its own. This version works on Express 4 and on Express 5.
import express from "express";

const app = express();

// In a project, import this from utils/HttpError.js instead.
class HttpError extends Error {
  constructor(status, message) {
    super(message);
    this.status = status;
  }
}

const items = [{ id: 1, title: "First Item" }];

// This stands in for a database call such as Item.findById(id).
const findById = async (id) => items.find((item) => item.id === Number(id));

// Express 4 needs next here, so the catch can hand the error over.
const getItem = async (req, res, next) => {
  try {
    const item = await findById(req.params.id);

    if (!item) throw new HttpError(404, "Item not found.");
    res.status(200).json(item);
  } catch (error) {
    // Express 4 does not catch errors in async functions. Pass them on by hand.
    next(error);
  }
};

app.get("/api/items/:id", getItem);

app.use((error, req, res, next) => {
  if (error instanceof HttpError) {
    return res.status(error.status).json({ error: error.message });
  }

  console.error(error);
  res.status(500).json({ error: "An unexpected server error occurred." });
});

app.listen(3000, (error) => {
  if (error) throw error; // e.g. the port is already in use
  console.log("Server listening on http://localhost:3000");
});

// Try it from a second terminal:
// curl -i http://localhost:3000/api/items/1
// curl -i http://localhost:3000/api/items/99

Pro-Tip: On Express 4, an error thrown in an async function with no try and catch never reaches the error handler, and on current versions of Node it stops the whole server. Run npm ls express before you copy an old controller.

Serve React From Express

This is for going live, when Express serves the finished React site. Run npm run build first, which puts the site in server/public because of the outDir in vite.config.js. The old app.get("/*") line from my class projects crashes on Express 5, so this version uses app.use instead.

A full server.js with the React block after the API routes

In your own server.js, the part to add is the if block. It goes after the API routes and above the 404 handler.

// Runs on its own. Save it as server.js, then run: NODE_ENV=production node server.js
import express from "express";
import path from "node:path";
import { fileURLToPath } from "node:url";

const PORT = process.env.PORT || 3000;

// The public folder that sits next to this file. It is built from this file's
// own address, so it works no matter which folder you run node from.
const publicDir = fileURLToPath(new URL("./public", import.meta.url));

const app = express();

app.use(express.json({ limit: "100kb" }));

// The API routes go first.
app.get("/api/health", (req, res) => {
  res.status(200).json({ status: "ok" });
});

// Only when the site is live. On your own computer Vite serves React instead.
if (process.env.NODE_ENV === "production") {
  // Serves the built files: index.html, JavaScript, CSS, and images.
  app.use(express.static(publicDir));

  app.use((req, res, next) => {
    // Unknown /api paths still get a JSON 404 from the handler below this block.
    if (req.path.startsWith("/api")) return next();
    // Only page loads get index.html. A POST to a wrong URL is still a 404.
    if (req.method !== "GET") return next();
    // Every other URL gets index.html, and React Router picks the page.
    res.sendFile(path.join(publicDir, "index.html"));
  });
}

// No route above matched.
app.use((req, res) => {
  res.status(404).json({ error: "Route not found." });
});

// sendFile ends up here when public/index.html does not exist yet.
app.use((error, req, res, next) => {
  console.error(error);
  res.status(500).json({ error: "An unexpected server error occurred." });
});

app.listen(PORT, (error) => {
  if (error) throw error; // e.g. the port is already in use
  console.log(`🚀 Server listening on http://localhost:${PORT}`);
});

Pro-Tip: Run npm run build before you start it. Until then public/index.html does not exist and every page gives a 500. The host also has to set NODE_ENV to production, or the whole block is skipped.

Split App And Server For Testing

This is how Rev is built. app.js builds the app and server.js starts it, so a test can use the app without opening a real port or a database.

server/app.js

import express from "express";

// A function that builds the app and hands it back without starting it.
// There is no app.listen in this file on purpose.
export function createApp() {
  const app = express();

  app.use(express.json({ limit: "100kb" }));

  app.get("/api/health", (req, res) => {
    res.status(200).json({ status: "ok" });
  });

  // No route above matched.
  app.use((req, res) => {
    res.status(404).json({ error: "Route not found." });
  });

  // server.js and the tests both get the same app from here.
  return app;
}

server/server.js for the split

This is the whole file. It only builds the app and opens the port.

import { createApp } from "./app.js";

const PORT = process.env.PORT || 3000;

// Build the app, then open the port. Tests import app.js and skip this file.

app.listen(PORT, (error) => {
  if (error) throw error; // e.g. the port is already in use

server/test/health.test.js

// node:test, node:assert, and node:events come with Node. Nothing to install.
import test from "node:test";
import assert from "node:assert/strict";
import { once } from "node:events";
import { createApp } from "../app.js";

test("GET /api/health answers ok", async () => {
  // Port 0 means any free port, so the test never clashes with a running server.
  const server = createApp().listen(0);

  // Wait until the port is really open before asking which one it is.
  await once(server, "listening");
  const { port } = server.address();

  try {
    // fetch comes with Node 18 and newer.
    const response = await fetch(`http://127.0.0.1:${port}/api/health`);

    assert.equal(response.status, 200);
    // deepEqual compares what is inside the two objects.
    assert.deepEqual(await response.json(), { status: "ok" });
  } finally {
    // Always close the server, even when a check fails, or the test never ends.
    server.close();
  }
});

Node Built-In Tools

Random values and IDs

// Runs on its own. node:crypto comes with Node, so there is nothing to install.
import { randomBytes, randomUUID } from "node:crypto";

// A unique ID, such as 3b241101-e2bb-4255-8caf-4136c566a962.
const id = randomUUID();

// 32 random bytes written as hex is a 64 character secret.
const secret = randomBytes(32).toString("hex");

console.log("ID:", id);
console.log("Secret:", secret);

Pro-Tip: Never use Math.random() for a secret, a token, or a password reset link. Its values can be guessed. randomBytes and randomUUID are made for this.

Get a file path relative to the current file

// Runs on its own. node:url comes with Node, so there is nothing to install.
import { fileURLToPath } from "node:url";

// import.meta.url is the address of this file, such as file:///Users/you/project/server/config/env.js
// new URL("../.env", ...) goes up one folder from this file and points at .env.
// fileURLToPath turns that address into a normal path.
const envPath = fileURLToPath(new URL("../.env", import.meta.url));

console.log(envPath);

Pro-Tip: A plain path such as "./.env" is read from the folder you ran node in, not from the folder the file is in. This way always starts from the file itself.

Read a file

// Runs on its own. node:fs comes with Node, so there is nothing to install.
import { readFile } from "node:fs/promises";

try {
  // "utf8" gives you text. Without it you get raw bytes.
  const text = await readFile("notes.txt", "utf8");

  console.log(text);
} catch (error) {
  // ENOENT means there is no file with that name.
  if (error.code === "ENOENT") {
    console.error("notes.txt was not found in this folder.");
  } else {
    // Any other problem is unexpected, so let it stop the script.
    throw error;
  }
}

Pro-Tip: Never build the file name from something a visitor sent, such as req.params.name. A name like ../../.env would let them read any file on the server.

Shut down cleanly

Lets running requests finish and closes the database before the process stops.

// Runs on its own. Save it as server.js, run node server.js, then press Ctrl + C.
import express from "express";

const PORT = process.env.PORT || 3000;

const app = express();

app.get("/api/health", (req, res) => {
  res.status(200).json({ status: "ok" });
});

// This stands in for closing the database.
// Postgres: await pool.end();
// MongoDB:  await mongoose.disconnect();
const closeDatabase = async () => {
  console.log("Database closed.");
};

// Keep what app.listen gives back, because that is the thing you close.
const server = app.listen(PORT, (error) => {
  if (error) throw error; // e.g. the port is already in use
  console.log(`🚀 Server listening on http://localhost:${PORT}`);
});

const shutdown = () => {
  console.log("Shutting down...");

  // Stop taking new requests. The function inside runs once the open ones finish.
  server.close(async () => {
    await closeDatabase();
    process.exit(0);
  });

  // If a request never finishes, stop anyway after 10 seconds.
  // unref() means this timer alone does not keep the process running.
  setTimeout(() => process.exit(1), 10000).unref();
};

// SIGINT is Ctrl + C. SIGTERM is what a host sends before it stops the server.
// once means a second Ctrl + C is not caught, so it stops the process right away.
process.once("SIGINT", shutdown);
process.once("SIGTERM", shutdown);
