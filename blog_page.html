How This Blog Was Made

Nothing fancy. I planned the pages first, wrote one stylesheet built on CSS variables, and used a small script to stamp the same header and footer onto every page so I did not type them ten times. The finished site is plain HTML, CSS and a little JavaScript, so you can build it by hand with the steps below, or just copy the starters/blog-template folder.

Open the finished blog template

  • Plan the pages first: home, one page per post, about, and 404.
  • Put every color, font and size in one :root block, so a client rebrand is one edit.
  • Make each post its own HTML file, so Google and link previews can read it.
  • Use the same card for every post, so the home page always looks even.
  • Keep JavaScript small and optional. The site still works if it fails to load.

  about.html              About the author and the contact form
  404.html                Page not found
  posts/                  One HTML file per post
  css/style.css           All the styles. Brand settings are at the top.
  js/main.js              Phone menu and topic filter buttons
  scripts/list-posts.mjs  Rebuilds the post list on the home page
  images/                 Photos

Step 3 The JavaScript

This runs the phone menu and the topic filter buttons. Every page also has one tiny script in the head that adds a js class, so the phone menu only folds away when JavaScript is on.

js/main.js

// Small helpers for the blog. The site still works if this file fails to load.

// Phone menu: the button shows and hides the links.
const menuButton = document.querySelector(".menu-button");
const siteNav = document.getElementById("site-nav");

// Only when both exist on this page, so a page without a menu gives no error.
if (menuButton && siteNav) {
  menuButton.addEventListener("click", () => {
    // toggle adds the class when it is missing and removes it when it is there.
    // It gives back true when the menu is now open.
    const isOpen = siteNav.classList.toggle("is-open");
    // Tells screen readers whether the menu is open.
    menuButton.setAttribute("aria-expanded", String(isOpen));
  });
}

// Category buttons on the home page hide the posts that do not match.
const filterButtons = document.querySelectorAll(".filter");
const postCards = document.querySelectorAll("[data-category]");
const resultMessage = document.getElementById("filter-result");

filterButtons.forEach((button) => {
  button.addEventListener("click", () => {
    // dataset.filter reads the data-filter attribute of the button that was clicked.
    const category = button.dataset.filter;
    let shown = 0;

    // Mark the clicked button as pressed and every other button as not pressed.
    filterButtons.forEach((other) => other.setAttribute("aria-pressed", String(other === button)));

    postCards.forEach((card) => {
      // A card matches when All was clicked, or when its data-category is the same as the button.
      const matches = category === "all" || card.dataset.category === category;
      // hidden takes the card off the page, also for screen readers.
      card.hidden = !matches;
      if (matches) shown += 1;
    });

    // Says how many posts are showing, with "post" for one and "posts" for any other number.
    resultMessage.textContent = `Showing ${shown} ${shown === 1 ? "post" : "posts"}.`;
  });
});

The one line in every head

The box is a small whole page, so you can see where the line goes. The line itself is the script tag in the head.

<!DOCTYPE html>
<html lang="en">

<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Build Notes</title>
  <link rel="stylesheet" href="css/style.css">
  <!-- Adds class="js" to the html tag right away, before the page is drawn.
       The CSS only folds the phone menu away when that class is there. -->
  <script>document.documentElement.classList.add("js");</script>
</head>

<body>
  <p>With JavaScript on, the html tag of this page now has class="js".</p>
</body>

<p>A small coin battery on the motherboard keeps the clock running and remembers firmware settings while the computer is unplugged. After several years it can run out.</p>
<h2>Signs the battery is low</h2>
<ul>
  <li>The date and time reset when the computer is unplugged.</li>
  <li>Firmware settings go back to defaults.</li>
  <li>The computer shows a battery warning when it starts.</li>
</ul>
<h2>Steps</h2>
<ol>
  <li>Shut down, switch off the power supply and unplug the computer.</li>
  <li>Touch a metal part of the case to discharge static.</li>
  <li>Find the round battery on the motherboard. Most boards use a CR2032.</li>
  <li>Press the small clip and lift the old battery out.</li>
  <li>Put the new one in with the same side facing up.</li>
  <li>Plug in, start up and set the date and your settings again.</li>
</ol>
<div class="callout"><strong>Check first</strong> Your motherboard manual shows where the battery is and which type it takes.</div>

Add A New Post

  1. Copy any post in the posts folder and give it a new name. Use lowercase words with dashes, such as posts/best-budget-build.html. That name becomes the web address, so pick it carefully.
  2. In the new file, change the <title>, the three description and title <meta> tags, the <h1>, the tag, the date in both datetime and the text, the read time, the photo, and the text inside <div class="prose">.
  3. Put the photo in the images folder and set its width and height to the real size of the photo.
  4. Run the list script. The new post shows up at the top of the home page, and every older post stays.
  5. Update the Older post and Newer post links at the bottom of the new post and the post before it.

Keep The Old Posts

Old posts get lost when someone edits the home page list by hand and forgets one. This script fixes that. It reads every file in the posts folder and rebuilds the list, newest first, so a post stays on the home page for as long as its file exists. It needs Node and nothing else.

Run it after you add, edit or delete a post

node scripts/list-posts.mjs

scripts/list-posts.mjs

// Rebuilds the post list on the home page from the files in posts/.
// Run it after you add, edit or delete a post:   node scripts/list-posts.mjs
//
// Every post file in posts/ gets a card, newest first, so an old post can
// never be lost from the home page. The featured post at the top of
// index.html is left out of the list, because it is already shown there.
// Needs Node 20.11 or newer, because of import.meta.dirname. No packages to install.

import fs from "node:fs";
import path from "node:path";

// import.meta.dirname is the folder this script is in. One step up from scripts is the main folder.
const root = path.join(import.meta.dirname, "..");
const indexFile = path.join(root, "index.html");
const postsFolder = path.join(root, "posts");

// Pull one value out of a post file, or stop with a clear message.
function find(html, pattern, what, file) {
  const match = html.match(pattern);
  if (!match) {
    throw new Error(`${file} is missing ${what}.`);
  }
  return match[1].trim();
}

// Reads one post file and pulls out everything a card needs.
function readPost(file) {
  const html = fs.readFileSync(path.join(postsFolder, file), "utf8");
  const header = find(html, /<header class="article-header">([\s\S]*?)<\/header>/, "the article header", file);
  const hero = find(html, /<figure class="article-hero">([\s\S]*?)<\/figure>/, "the article photo", file);
  const image = find(hero, /(<img [^>]*>)/, "an <img> in the article photo", file);

  return {
    // The file name without .html. It becomes the link to the post.
    slug: file.replace(/\.html$/, ""),
    title: find(header, /<h1>([\s\S]*?)<\/h1>/, "an <h1>", file),
    category: find(header, /<span class="tag">([\s\S]*?)<\/span>/, "a tag", file),
    date: find(header, /<time datetime="([^"]+)"/, "a date", file),
    readTime: find(header, /<span>(\d+) min read<\/span>/, "a read time", file),
    excerpt: find(html, /<meta name="description" content="([^"]*)"/, "a description", file),
    src: find(image, /src="\.\.\/([^"]+)"/, "a photo src", file),
    alt: find(image, /alt="([^"]*)"/, "photo alt text", file),
    width: find(image, /width="(\d+)"/, "a photo width", file),
    height: find(image, /height="(\d+)"/, "a photo height", file),
  };
}

// Turns 2026-01-15 into January 15, 2026. UTC stops the day from shifting with the time zone.
function niceDate(iso) {
  return new Date(`${iso}T00:00:00Z`).toLocaleDateString("en-US", {
    month: "long",
    day: "numeric",
    year: "numeric",
    timeZone: "UTC",
  });
}

// Builds the HTML for one card. The spaces at the start match the indent in index.html.
function card(post) {
  return `        <li data-category="${post.category}">
          <article class="post-card">
            <img class="post-card__image" src="${post.src}" alt="${post.alt}" width="${post.width}" height="${post.height}" loading="lazy">
            <div class="post-card__body">
              <span class="tag">${post.category}</span>
              <h3 class="post-card__title"><a href="posts/${post.slug}.html">${post.title}</a></h3>
              <p class="post-card__excerpt">${post.excerpt}</p>
              <p class="meta"><time datetime="${post.date}">${niceDate(post.date)}</time><span aria-hidden="true">&middot;</span><span>${post.readTime} min read</span></p>
            </div>
          </article>
        </li>`;
}

const index = fs.readFileSync(indexFile, "utf8");
// Find the two marker comments in index.html. indexOf gives -1 when the text is not there.
const start = index.indexOf("<!-- POSTS START");
const end = index.indexOf("<!-- POSTS END -->");
if (start === -1 || end === -1) {
  throw new Error("index.html needs the POSTS START and POSTS END comments around the post list.");
}

// The post in the hero at the top. ?.[1] gives undefined instead of an error when there is none.
const featured = index.match(/class="hero__title"><a href="posts\/([^"]+)\.html"/)?.[1];
// Every .html file in posts is read, the featured one is taken out, and the rest are sorted newest first.
const posts = fs
  .readdirSync(postsFolder)
  .filter((file) => file.endsWith(".html"))
  .map(readPost)
  .filter((post) => post.slug !== featured)
  .sort((a, b) => b.date.localeCompare(a.date));

// Keep everything up to the end of the POSTS START line, put the new cards in,
// then keep everything from POSTS END on.
const startLineEnd = index.indexOf("\n", start) + 1;
const updated = index.slice(0, startLineEnd) + posts.map(card).join("\n") + "\n        " + index.slice(end);
fs.writeFileSync(indexFile, updated);

console.log(`Listed ${posts.length} posts on the home page${featured ? `, plus ${featured} as the featured post` : ""}.`);

Pro-Tip: The script copies the title, the description and the alt text of each post straight into the home page. A plain < or & in one of them can break the list, so write &lt; and &amp; in the post file.

Rules for old posts

  • Never rename a post file. The file name is its web address, and old links from Google and social media will break.
  • Never change the date of an old post. Fix a typo, but keep the original date so the order stays right.
  • To take a post down, delete its file and run the script. Any link to it then shows the 404 page.
  • If a post fails to show up, the script names the file and what is missing, such as an <h1> or a date, and does not touch the home page.
  • To feature a different post, change the link in the hero at the top of index.html, then run the script so the old featured post goes back into the list.

Move Posts From A Client's Old Site

  1. Make a post file for each old post, using the steps in Add A New Post.
  2. Use the same file name as the old web address when you can. For example, example.com/blog/spring-sale becomes posts/spring-sale.html.
  3. Use the post's original date, not today's date.
  4. Copy the text into <div class="prose">. Use <h2> for section titles, <p> for paragraphs and <ul> for lists. Paste as plain text so the old site's styles do not come with it.
  5. Download the old photos into the images folder, and write real alt text for each one.
  6. Run the list script, then send each old web address to its new one with a redirect, so old links keep working.

Redirects on Netlify: a file named _redirects in the main folder

Each line is the old address, the new address, and 301, which tells Google the move is permanent.

/blog/spring-sale       /posts/spring-sale.html       301
/blog/how-we-started    /posts/how-we-started.html    301

Redirect on GitHub Pages: a page saved at the old address

GitHub Pages cannot do real redirects. Save this as the old address, for example blog/spring-sale/index.html, and it sends visitors to the new page.

<!DOCTYPE html>
<html lang="en">

<head>
  <meta charset="UTF-8">
  <title>This post has moved</title>
  <!-- Tells Google which address is the real one. -->
  <link rel="canonical" href="https://example.com/posts/spring-sale.html">
  <!-- 0 means: go to the new address right away. -->
  <meta http-equiv="refresh" content="0; url=/posts/spring-sale.html">
</head>

<body>
  <!-- A link for the rare browser that does not follow the line above. -->
  <p>This post has moved. <a href="/posts/spring-sale.html">Read it here</a>.</p>
</body>

</html>

Connect The Forms

The newsletter and contact forms send nothing until you connect them. Make a free form at a service such as Formspree, then paste the address it gives you into the action on both forms. To use your own Express server instead, point the action at your route, such as /api/contact.

<!DOCTYPE html>
<html lang="en">

  <link rel="stylesheet" href="css/style.css">

  <form class="inline-form" action="https://formspree.io/f/YOUR_FORM_ID" method="post">
    <label class="visually-hidden" for="newsletter-email">Email address</label>
    <!-- name="email" is the label the form service uses for the value. -->
    <input id="newsletter-email" name="email" type="email" autocomplete="email" placeholder="you@example.com" required>
    <button class="button" type="submit">Subscribe</button>
  </form>
</body>

</html>

Pro-Tip: A public form attracts spam bots within days. Turn on the spam protection your form service offers before the site goes live, and send yourself a test message from the live site, not from a file opened on your computer.

Before Handing It To A Client

  • Every placeholder name, photo and # link is replaced.
  • Both forms are connected and tested on the live site.
  • Every photo has real alt text and the right width and height.
  • The list script has been run, and every post shows on the home page.
  • The site looks right on a phone, in light mode and in dark mode.
  • You can reach every link and button with the Tab key.
  • Old web addresses from the client's previous site redirect to the new posts.
